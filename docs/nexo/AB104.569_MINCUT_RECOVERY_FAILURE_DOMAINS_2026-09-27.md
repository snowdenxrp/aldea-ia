# Nexo AB104.569 — Minimum-cut analysis for correlated recovery failures

Date: 2026-09-27

## Evidence
Classical Byzantine quorum systems require more than simple membership counts: safety depends on quorum intersections that cannot be entirely contained in a tolerated faulty set. Malkhi/Reiter formalize this through fail-prone systems and Byzantine quorum conditions. ## Finding
For Nexo recovery roots, a numeric threshold is safe only relative to an explicit failure-domain model. If multiple roots share a dependency that can compromise them together, counting them separately overstates independence.

Model recovery dependencies as a graph/hypergraph:
Root -> key -> hardware -> operator -> identity provider -> network/provider -> continuity evidence.

A failure set is dangerous when removing/compromising it can invalidate the protected recovery claim. Minimum-cut analysis can identify the smallest correlated dependency set separating the recovery authority from its trusted evidence or enforcement boundary.

## Effective threshold
Do not define effective recovery strength as merely N roots or N signatures.
Instead evaluate:
- quorum validity;
- quorum intersection;
- tolerated Byzantine/failure sets;
- dependency closure;
- failure-domain independence;
- availability requirements;
- evidence independence.

If several apparent roots collapse through one common dependency, the effective independent set is smaller. If no admissible recovery quorum remains after closure, recovery must not promote authority.

## Important nuance
A graph cut is not automatically a security proof. The cut is meaningful only after the dependency graph has been defined for the specific claim. Missing dependencies can produce a false independence result.

Therefore candidate algorithm:
1. Define protected claim.
2. Enumerate recovery roots.
3. Expand transitive dependencies.
4. Identify correlated failure domains/hyperedges.
5. Compute minimal failure sets capable of invalidating the claim.
6. Evaluate every admissible recovery quorum against those sets.
7. Require the configured Byzantine-safety condition, not merely a majority.
8. If the independence predicate is UNKNOWN, do not promote recovery authority.

## Key distinction
This is stronger than simply computing a minimum vertex cut over machines. A single cloud identity root, administrator, vendor signing root, or provisioning authority may represent a hyperedge connecting many apparently separate nodes.

CORRELATION != COLOCATION
MIN_CUT != SECURITY_PROOF
ROOT_COUNT != INDEPENDENT_ROOT_COUNT
QUORUM_SIZE != FAILURE_TOLERANCE
SIGNATURE_COUNT != TRUST_INDEPENDENCE
