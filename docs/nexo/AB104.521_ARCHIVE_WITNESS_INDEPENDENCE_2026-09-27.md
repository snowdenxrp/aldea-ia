# AB104.521 — independent archival witnesses and evidence availability

## Evidence
RFC 9162 describes monitoring/auditing of transparency logs and says that absence of an entry from monitors' copies, or failure to provide an inclusion proof, can be evidence of log misbehavior; it also warns that a misbehaving log can present inconsistent views, motivating cross-observation. citeturn0search1 NIST treats digital-evidence preservation as a distinct lifecycle problem involving preservation and integrity. citeturn0search0turn0search3

## Core finding
Multiple archival copies improve availability, but replica count does not establish independent evidence. Nexo must model the trust and failure dependencies of each witness.

Candidate witness tuple:
`Witness = {WitnessID, ArchiveID, TrustBasis, FailureDomains, ProviderDependencies, Epoch, Checkpoint, Coverage, Status}`

Candidate admissible set:
`Q = {S | coverage(S) >= requiredCoverage AND independence(S) >= requiredIndependence AND status(S)=VALID}`

Thresholds remain claim-specific; no security score is assigned here.

## Independence
`REPLICA_COUNT != INDEPENDENCE`
`WITNESS_COUNT != INDEPENDENCE`
`GEOGRAPHIC_DIVERSITY != TRUST_INDEPENDENCE`
`DIFFERENT_SERVERS != DIFFERENT_TRUST_BASES`
`DIFFERENT_PROVIDERS != INDEPENDENT_IF_COMMON_DEPENDENCY`

Common dependencies may include the same signing root, identity provider, deployment pipeline, operator, cloud control plane, archive key, network authority, or software artifact. A correlated compromise can therefore defeat several nominal witnesses simultaneously.

## Omission and negative evidence
A witness lacking receipt X cannot prove X never existed unless its checkpoint/history coverage is known to cover the relevant interval. RFC 9162's monitoring model similarly relies on complete or consistency-checked tree coverage rather than a single local absence. citeturn0search1

`LOCAL_ABSENCE != GLOBAL_NONEXISTENCE`
`INCOMPLETE_HISTORY != NEGATIVE_EVIDENCE`

If two independently observed signed checkpoints for the same archive identity conflict, preserve both and classify the archive state as UNKNOWN rather than silently selecting one.

`CONFLICTING_SIGNED_CHECKPOINTS_FOR_SAME_ARCHIVE_ID => UNKNOWN_ARCHIVE_STATE`

## Equivocation
Flow:
`CHECKPOINT_OBSERVED → CHECKPOINT_VALIDATED → CROSS_WITNESS_COMPARED → CONSISTENT | CONFLICTING`

Conflict:
`CONFLICTING → ARCHIVE_QUARANTINED → TRUST_REASSESSMENT → RECOVERY_OR_UNKNOWN`

RFC 9162's consistency proofs establish whether one committed tree extends another; they do not establish which conflicting trust domain is truthful. citeturn0search1

## Correlated loss
If all witnesses depend on one archive provider, key, identity root, backup system, or control plane, simultaneous loss/compromise is one failure domain despite many replicas.

`COMMON_DEPENDENCY_CLOSURE => EFFECTIVE_WITNESS_REDUCTION`

This reuses the dependency-closure methodology established in AB104.503–504.

## Availability versus truth
`AVAILABILITY != AUTHENTICITY != CURRENTNESS != CLAIM_TRUTH`

An unavailable witness does not prove its last checkpoint was wrong. A reachable witness does not make its evidence current or truthful. If the minimum independent set cannot be established, protected decisions relying on the evidence remain UNKNOWN/quarantined rather than lowering safety thresholds merely to restore availability.

## Replacement
A new witness can replicate historical evidence without becoming an independent trust basis if it was provisioned from the same compromised archive or root.

`NEW_REPLICA != NEW_TRUST_BASIS`
`RESTORED_BACKUP != INDEPENDENT_WITNESS`
`REPLICATION != INDEPENDENT_OBSERVATION`

## Effect-history consequence
Independent witnesses can strengthen evidence that an archived provider receipt existed and was not altered within the archive system. They do not, by themselves, prove the provider's underlying claim beyond the authenticated receipt scope.

`WITNESS_CONFIRMATION_OF_RECEIPT != EXTERNAL_WORLD_TRUTH`

## Status
Research complete. Independent archival witnesses improve detection and survivability only when their trust/failure dependencies and history coverage are explicit. Replica count alone cannot promote evidence or authority.
