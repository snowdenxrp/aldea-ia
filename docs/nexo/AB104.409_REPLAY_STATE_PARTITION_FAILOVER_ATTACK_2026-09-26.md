# Nexo AB104.409 — Replay-State Durability Under Partition, Replication Lag and Failover

Date: 2026-09-26
Status: RESEARCH / DESIGN ONLY
Continuity anchor: AB104.408 → AB104.409
Implementation: NOT PERFORMED

## Research question

Can Nexo make replay/deduplication decisions safely when replay state is replicated, partitioned, rolled back, or concurrently updated across regions?

## Evidence reviewed

Amazon SQS documents that standard queues use at-least-once delivery and may deliver the same message more than once. FIFO deduplication is bounded by a five-minute interval; retries after that interval can create duplicates. Visibility-timeout expiry can also lead to repeated processing. citeturn0search1turn0search2

SQS FIFO provides ordering within a message group and a deduplication identifier, but the documented deduplication interval is finite. Therefore a provider's “exactly-once” feature cannot automatically be generalized into indefinite Nexo effect identity. citeturn0search5turn0search14

DynamoDB conditional writes provide a concrete optimistic-concurrency primitive: a write can require a version to match before mutation. AWS also documents that global-table replication can have conflicts and that MREC transactions are atomic only in the originating region; replicated regions can observe partial transaction state. citeturn0search4turn0search7turn0search16

## Core finding

Replay protection is not merely a cryptographic property.

`REPLAY_SAFETY = IDENTITY + CURRENT_STATE + DURABLE_DECISION + CONCURRENCY_CONTROL`

A signature/MAC can prove message origin/integrity, but a participant still needs an authoritative decision about whether that exact lineage/effect is currently admissible.

## Critical partition attack

Suppose regions R1 and R2 both believe EFFECT_ID=E has not yet been consumed.

1. R1 receives E.
2. R2 receives E before R1's replay state propagates.
3. Both locally accept.
4. Network partition prevents reconciliation.
5. Both cross the external effect boundary.

If the effect is non-idempotent, the result can be two external effects even though each local replay check was internally valid.

Therefore:

`LOCAL_REPLAY_CHECK != GLOBAL_REPLAY_EXCLUSION`

For an effect whose safety requires global uniqueness, Nexo needs a single authoritative linearization domain, a proven strongly consistent coordination mechanism, or an effect/provider protocol that itself enforces equivalent uniqueness.

## Replication lag attack

A stale replica may contain:

`REPLAY_STATE = UNUSED`

while the authoritative/latest state is:

`REPLAY_STATE = CONSUMED`

A read from the stale replica must not be used as proof of admissibility for a protected effect.

Candidate invariant:

`STALE_REPLAY_STATE_CANNOT_GRANT_AUTHORITY`

This aligns with the broader Nexo rule that historical/current state must be separated.

## Rollback attack

A replay ledger snapshot is restored to an earlier point:

`CONSUMED(E) → UNUSED(E)`

If the system then accepts E again, rollback has converted historical consumption into apparent freshness.

Therefore replay state needs anti-rollback protection when it is security-critical.

Candidate controls:

- monotonic protected generation;
- durable epoch/fence;
- append-only/event-sourced consumption record;
- trusted checkpoint/continuity anchor;
- rollback detection;
- quarantine when monotonicity cannot be established.

No single mechanism is selected yet.

## Multi-region conflict

DynamoDB global-table evidence demonstrates that consistency semantics depend on the chosen mode: MREC can reconcile concurrent writes and can expose partially replicated transactions, while MRSC provides stronger cross-region read/write semantics but has different transaction constraints. citeturn0search6turn0search8

Nexo therefore cannot encode “multi-region” as a safety property by itself.

Candidate protected property:

`REPLAY_DECISION_CONSISTENCY`

must be specified independently of deployment topology.

## Duplicate vs retry vs new effect

The replay layer must distinguish:

- duplicate delivery of the same message;
- retry of the same logical effect;
- new attempt for the same effect;
- recovery attempt;
- genuinely new effect.

Candidate identity relation:

`OPERATION_ID 
eq EFFECT_ID 
eq ATTEMPT_ID 
eq RECOVERY_ATTEMPT_ID`

A provider deduplication identifier can help at one boundary, but it does not automatically establish Nexo's global semantic identity.

## Ordering attack

FIFO ordering can constrain messages within a provider-defined group, but Nexo's protected ordering may span:

- different queues;
- different providers;
- callbacks;
- external resources;
- recovery paths.

Therefore:

`PROVIDER_ORDERING != GLOBAL_AUTHORITY_ORDERING`

If an operation requires a specific predecessor, the participant must validate the predecessor against authoritative state.

## Failover attack

A failover replica may have:

- stale replay state;
- stale authority epoch;
- stale fence generation;
- stale capability generation;
- incomplete footprint closure;
- incomplete reconciliation.

Failover must therefore preserve the semantics required by the protected property, not merely restore service availability.

Candidate rule:

`FAILOVER_WITHOUT_REQUIRED_STATE_FRESHNESS => HOLD/REVALIDATE`

If freshness cannot be established, high-consequence effects must not silently proceed.

## Availability trade-off

There is an unavoidable design fork for some protected effects:

A. allow both regions to admit during partition → availability increases, but global uniqueness may fail;

B. require authoritative coordination → uniqueness can be preserved, but partition can force HOLD/REJECTED;

C. delegate uniqueness to an external effect provider with proven semantics → local coordination burden can decrease, but provider semantics become part of the TCB/evidence dependency.

Nexo should not hide this trade-off behind a generic “distributed idempotency” abstraction.

## Candidate replay-state contract

For a protected effect:

- EFFECT_ID
- OPERATION_ID
- ATTEMPT_ID
- RESOURCE_INCARNATION
- AUTHORITY_EPOCH
- FENCE_GENERATION
- CONSUMPTION_STATUS
- LINEAGE_SCHEMA_VERSION
- REPLAY_STATE_GENERATION
- LAST_ACCEPTED_SEQUENCE / equivalent, if ordering matters
- durable outcome/reference
- invalidation generation
- evidence/provenance of the replay decision

Candidate state:

`UNSEEN → ADMITTED → CONSUMED/ATTEMPTED → FINALIZED`

with explicit:

`UNKNOWN | CONFLICT | QUARANTINED | RECONCILIATION_REQUIRED`

## Important boundary

Even an atomically durable replay decision does not prove the external effect happened exactly once.

Example:

1. replay ledger marks E consumed;
2. process crashes;
3. external request never happened.

If E is retried, replay state may correctly reject it while the external effect remains absent.

Conversely:

1. external request happens;
2. process crashes before recording consumption;
3. retry is admitted;
4. duplicate external effect occurs.

Thus:

`REPLAY_ATOMICITY != EXTERNAL_EFFECT_ATOMICITY`

This directly preserves the existing Nexo distinction between control linearization and external confirmation.

## Attack matrix

| Attack | Unsafe inference | Required response |
|---|---|---|
| partitioned dual admission | local UNUSED => globally unused | authoritative coordination or HOLD |
| stale replica | replica says UNUSED => admissible | current-state validation |
| replay-ledger rollback | restored UNUSED => safe retry | anti-rollback/quarantine |
| dedup window expiry | provider dedup => permanent identity | explicit semantic lifetime |
| failover | service recovered => state current | freshness/epoch validation |
| duplicate delivery | new delivery => new effect | stable identity + replay state |
| missing replay record | no record => never happened | UNKNOWN/reconciliation |
| consumed but no external attempt | consumed => effect happened | separate effect state |
| external attempt but no record | no record => safe retry | UNKNOWN/reconciliation |
| cross-region transaction | local commit => global atomicity | participant-specific state |
| provider FIFO | provider order => Nexo global order | explicit protected ordering |
| concurrent regions | both local checks pass | one authority/strong coordination/provider guarantee |

## Candidate invariants

- `LOCAL_REPLAY_CHECK != GLOBAL_REPLAY_EXCLUSION`
- `STALE_REPLAY_STATE_CANNOT_GRANT_AUTHORITY`
- `ROLLBACK_CANNOT_RESTORE_CONSUMED_EFFECT_TO_UNSEEN`
- `PROVIDER_DEDUP_WINDOW != NEXO_EFFECT_IDENTITY_LIFETIME`
- `PROVIDER_ORDERING != GLOBAL_AUTHORITY_ORDERING`
- `FAILOVER_REQUIRES_REQUIRED_STATE_FRESHNESS`
- `MISSING_REPLAY_RECORD != EVIDENCE_OF_NON_EXECUTION`
- `REPLAY_ATOMICITY != EXTERNAL_EFFECT_ATOMICITY`
- `REPLAY_DECISION_MUST_BIND_TO_RESOURCE_INCARCATION_WHERE_REQUIRED`
- `REPLAY_DECISION_MUST_BIND_TO_AUTHORITY_GENERATION_WHERE_REQUIRED`
- `PARTITION_MUST_NOT_SILENTLY_WEAKEN_GLOBAL_UNIQUENESS`
- `DUPLICATE_DELIVERY != NEW_EFFECT`

## Residuals / not proven

- Exact replay-state topology for Nexo.
- Formal partition model and CAP-style trade-off per effect class.
- Formal anti-rollback mechanism.
- Multi-region linearization proof.
- Provider-specific durable idempotency semantics beyond bounded windows.
- Recovery after replay-state corruption/compromise.
- Exact relationship between replay state and external-effect reconciliation.
- Implementation correctness and fault-injection evidence.
