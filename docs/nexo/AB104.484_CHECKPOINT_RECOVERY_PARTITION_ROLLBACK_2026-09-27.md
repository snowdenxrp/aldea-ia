# AB104.484 — checkpoint recovery under partition and rollback

RFC 9162 requires consistency proofs to demonstrate that a later Merkle tree extends an earlier tree. Conflicting signed tree heads for the same log provide evidence of equivocation; gossip allows observers to discover incompatible views. citeturn0search1turn0search0

For Nexo, a durable checkpoint is evidence of an observed log state, not a self-authorizing recovery command.

## Recovery cases

1. STALE CHECKPOINT + CONSISTENT NEW TREE: accept only after proving extension from the stored checkpoint.
2. CHECKPOINT + NO FRESH WITNESS: retain the last trusted state; do not promote absence of new evidence to proof of rollback.
3. CONFLICTING SIGNED CHECKPOINTS: treat as equivocation; quarantine affected evidence and require reconciliation.
4. QUORUM LOSS: loss of witnesses does not authorize lowering the safety threshold.
5. ROLLBACK ATTEMPT: a state older than the durable checkpoint cannot silently replace the checkpoint.
6. TRUST-DOMAIN COMPROMISE: compromised witnesses cannot certify their own replacement; re-enrollment requires an independently justified trust transition.

## Recovery boundary

A recovery protocol should distinguish:
CHECKPOINT_OBSERVED -> CHECKPOINT_VALIDATED -> CONSISTENCY_VERIFIED -> WITNESS_SET_VALIDATED -> RECOVERY_AUTHORIZED

No step may be skipped merely because availability is lost.

## Key distinction

A checkpoint proves that a log state was observed. It does not prove that the underlying external effect was true or authorized. Recovery of transparency evidence cannot rewrite provider effect history.

New invariants:
- STALE_CHECKPOINT != CURRENT_STATE
- NO_NEW_WITNESS != PROOF_OF_ROLLBACK
- CONFLICTING_CHECKPOINTS => QUARANTINE
- QUORUM_LOSS != SAFETY_THRESHOLD_REDUCTION
- OLD_CHECKPOINT != AUTHORIZATION_TO_ROLLBACK
- COMPROMISED_WITNESS_SET != AUTHORITY_TO_REENROLL_ITSELF
- RECOVERY_CHECKPOINT != EXTERNAL_EFFECT_CONFIRMATION
- CHECKPOINT_REPLACEMENT_REQUIRES_EXPLICIT_TRUST_TRANSITION
- CONSISTENCY_PROOF_REQUIRED_FOR_AUTOMATIC_FORWARD_PROMOTION

Evidence status: checkpoint consistency and gossip provide concrete mechanisms for detecting rollback/equivocation, while recovery authorization, witness independence, and external-effect reconciliation remain separate claims. No implementation or formal verification performed.
