# AB104.491 — Byzantine quorum reconfiguration and minimum safety condition

## Research
Reconfigurable Byzantine quorum systems show that membership changes can be modeled as changes to quorum systems, with explicit safety/availability/inclusion trade-offs and correctness requirements under Byzantine attacks. The key point is that reconfiguration safety depends on the relation between old and new quorum systems, not merely on member counts. citeturn0search12turn0academia36

BFT-SMaRt provides concrete implementation evidence for dynamic replica add/remove, while also documenting an operational limitation: currentView must be distributed consistently to replicas and clients. This is evidence that configuration dissemination itself is part of the trusted reconfiguration surface. citeturn0search2

Tendermint applies validator-set changes through committed application state and delays their effective use; its validator update model explicitly distinguishes the update from the later active set. citeturn0search0turn0search4

## Minimum mathematical condition
For Nexo, the minimum safety condition should not be expressed as `new_threshold > old_threshold` or as a fixed member-count rule. Candidate condition:

`∀ Q_old ∈ Quorums(E_old), ∀ Q_new ∈ Quorums(E_new):
  Q_old ∩ Q_new contains sufficient NON-COMPROMISED trust, OR
  an explicit trusted transition fence makes the old quorum unable to authorize after the fence.`

The second branch is essential for compromise recovery. If old witnesses are known compromised, requiring intersection through those witnesses is not a safe recovery mechanism; the system must instead establish a trusted fencing boundary and an independent recovery basis.

For Byzantine quorum systems, the surviving honest overlap must be sufficient for the protected property being preserved. Exact cardinality depends on the quorum model, fault bound, weighted voting, and failure-domain assumptions; no universal numeric threshold was adopted here.

## Epoch rule
A protected authority epoch `A_e` should be monotonic. An authorization is admissible only when:
`AUTH_EPOCH == CURRENT_EPOCH`
AND
`MEMBERSHIP_DIGEST == CURRENT_MEMBERSHIP_DIGEST`
AND
`TRUST_BASIS_EPOCH == CURRENT_TRUST_BASIS_EPOCH`
AND
`FENCE_REVISION >= CURRENT_FENCE_REVISION`.

Any stale epoch is historical evidence only.

## Compromise-aware reconfiguration
Candidate sequence:
`E_old ACTIVE → FENCE_COMMITTED → RECOVERY_BASIS_COMMITTED → E_new VALIDATED → CHECKPOINT_CONTINUITY_VERIFIED → E_new ACTIVATED`

The old set does not need to participate after `FENCE_COMMITTED` if the recovery authority is genuinely independent and authorized to establish the fence. If that independence cannot be demonstrated, the correct state is `UNKNOWN_AUTHORITY`, not an inferred safe quorum.

## Key invariants
- `MEMBER_COUNT != QUORUM_SAFETY`
- `THRESHOLD != TRUST_INDEPENDENCE`
- `OLD_NEW_INTERSECTION != AUTOMATIC_SAFETY_IF_INTERSECTION_IS_COMPROMISED`
- `FENCE_COMMITTED => OLD_EPOCH_CANNOT_AUTHORIZE_NEW_TRANSITIONS`
- `STALE_EPOCH => HISTORICAL_ONLY`
- `CONFIGURATION_DISTRIBUTION_IS_PART_OF_TCB`
- `NEW_THRESHOLD_REQUIRES_EXPLICIT_TRUST_BASIS`
- `UNKNOWN_TRUST_BASIS => UNKNOWN_AUTHORITY`
- `NUMERIC_QUORUM_ALONE != FAILURE_DOMAIN_INDEPENDENCE`
