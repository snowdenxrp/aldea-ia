# AB104.503 — dependency graph, SCC, minimum-cut and provenance closure

## Evidence
Strongly connected components (SCCs) partition a directed graph into maximal mutually reachable groups; Tarjan-style algorithms compute SCCs in linear time, and the algorithm has been formally proved in Why3, Coq and Isabelle. citeturn0search3turn0search5 NIST fault-tree analysis treats minimal cut sets as combinations of basic failures sufficient to produce a top failure and explicitly identifies common-cause failures shared across multiple components. citeturn0search24 NIST also uses minimum s-t cut sets to identify critical transitions whose failure disconnects desired system paths. citeturn0search1 Directed hypergraphs are materially more complex than ordinary graphs for SCC/transitive-reduction problems, so collapsing multi-party dependencies into ordinary edges can lose structure. citeturn0academia30

## Nexo dependency model
Use two related structures:
1. directed dependency graph for ordinary prerequisite edges;
2. directed hypergraph for joint/common-mode dependencies where one cause affects multiple authorities or where a claim requires a set of conditions together.

Each dependency edge/hyperedge should carry provenance:
`{source_claim, target_claim, relation, evidence_ids, authority_epoch, trust_basis, observed_at, validity_window}`.

## SCC / circularity
Compute SCCs before authority composition. Any SCC containing protected authority claims represents mutual dependency and cannot be treated as independently established merely because every node has a locally valid certificate.

Candidate disposition:
- singleton acyclic dependency → ordinary composition;
- SCC with an independent base invariant → explicitly discharge cycle using that base;
- SCC without an independent basis → `UNKNOWN_AUTHORITY` / quarantine.

SCC detection is algorithmically tractable on ordinary graphs; the formal proofs of Tarjan's algorithm show that the graph-analysis primitive itself can be given machine-checked correctness, although that does not prove Nexo's semantic interpretation of the graph. citeturn0search5

## Common-mode / minimum-cut
For an authority claim, define the failure goal as loss of an independent basis for authorization. Compute candidate minimal cuts over the dependency structure. A cut is meaningful only if its elements correspond to real shared failure/trust causes, not merely graph nodes.

NIST's common-cause analysis is directly relevant: physically or logically separate components can still share a common cause, and minimal cut sets expose combinations sufficient for system failure. citeturn0search24

Therefore:
`RAW_NODE_COUNT != FAILURE_DOMAIN_COUNT`
`RAW_SIGNER_COUNT != INDEPENDENT_TRUST_COUNT`
`MIN_CUT_CARDINALITY != AUTOMATIC_SECURITY_THRESHOLD`

A minimum cut is evidence about a modeled dependency graph, not proof of real-world independence.

## Hypergraph requirement
A certificate may depend on a conjunction such as `{membership, trust_basis, checkpoint}` as one semantic prerequisite. Representing this only as three independent edges can incorrectly imply that each dependency alone discharges the requirement. Hyperedges preserve the joint condition.

Conversely, a common cause such as `{shared_root}` affecting several witnesses should be represented as a shared dependency rather than duplicated independent edges.

## Provenance preservation
Every discharged assumption must retain a provenance chain to its evidence and trust basis. Recomputing the graph from current state must not erase the historical graph used for a prior authority decision.

Candidate record:
`DependencyAssessment = {GraphDigest, ClosureDigest, SCCDigest, CutSetDigest, Claim, Epoch, EvidenceRefs, TrustBasisRefs, Decision}`.

The graph digest binds the exact dependency view; evidence refs preserve why each edge/hyperedge existed; epoch prevents a current graph from silently rewriting a historical decision.

## Candidate authority gate
`ALLOW(C)` requires:
1. coherent dependency snapshot;
2. no undisclosed protected SCC;
3. every circular assumption discharged by an independent basis or explicit proof rule;
4. common-mode closure evaluated;
5. required hyperedges satisfied;
6. provenance complete;
7. graph/closure digest bound to the authority decision.

## Invariants
- `SCC != AUTOMATIC_AUTHORITY`
- `UNDISCHARGED_SCC => UNKNOWN_OR_QUARANTINE`
- `MIN_CUT != PROOF_OF_INDEPENDENCE`
- `COMMON_CAUSE => DEPENDENCY_COLLAPSE_FOR_INDEPENDENCE`
- `RAW_COUNT != EFFECTIVE_INDEPENDENCE`
- `GRAPH_DIGEST_MUST_BE_BOUND_TO_DECISION`
- `HISTORICAL_DEPENDENCY_GRAPH != CURRENT_GRAPH`
- `HYPEREDGE_CONJUNCTION != INDEPENDENT_EDGES`
- `FORMALLY_VERIFIED_GRAPH_ALGORITHM != VERIFIED_NEXO_SEMANTICS`

## Status
Research complete. No implementation or formal verification performed. Ordinary SCC analysis is a strong candidate for cycle detection; hypergraph modeling is needed where dependencies are conjunctive/common-mode. Minimum-cut analysis is useful for adversarial closure but must not be promoted into an independence proof by itself.

Next exact step: AB104.504 — research incremental/dynamic dependency closure and snapshot consistency: how to update SCC/common-mode/cut analysis when membership, trust basis, checkpoint, or fence changes without using a mixed or stale graph.
