## Resolved facts
- TestKitDefaults.BROKER_ID_OFFSET = 0.
- TestKitDefaults.CONTROLLER_ID_OFFSET = 3000.
- In non-combined KRaft TestKit, broker IDs start at 0 and controller IDs start at 3000.
- With setNumBrokerNodes(1) and setNumControllerNodes(1), the broker map contains ID 0 and the controller map contains ID 3000.
- TestKitNodes.Builder validates every setPerServerProperties key against the actual broker/controller ID sets before constructing the cluster.
- KafkaClusterTestKit.Builder.createNodeConfig(node, ...) applies the property overrides associated with the node's actual ID.
- KafkaClusterTestKit.build() stores BrokerServer instances in brokers keyed by node.id(), so brokers().get(0) is the exact broker object for the one-broker configuration.
- KafkaClusterTestKit.waitForReadyBrokers() waits for broker registration/unfencing and then waits for each broker metadata cache to observe all alive brokers.
- KafkaClusterTestKit.bootstrapServers() derives the actual bound broker listener ports from each BrokerServer, so a later runtime harness can address the target broker deterministically.
- KafkaClusterTestKit exposes brokers(), controllers(), nodes(), and waitForReadyBrokers() directly.

## G0 consequence
The previous concern about assuming perServerProperties key 0 is now resolved for the intended isolated one-broker/non-combined configuration. The target broker is deterministically ID 0; controller is ID 3000.
