# Nexo AB104.436 — Fence Contract Formal Attack

Date: 2026-09-26
Status: RESEARCH / DESIGN ONLY
Continuity: AB104.435 → AB104.436
Implementation: NOT PERFORMED

## Objective

Turn the Fence Contract into explicit state predicates and attack temporal races between authority rollover, resource mutation, recovery, and external-effect reconciliation.

## Abstract state

Let:

A = authority incarnation
G = authority/fence generation
R = resource incarnation
F = resource fence generation
O = operation/effect identity
P = policy/trust generation
Q = quarantine state

A request carries:

(A_req, G_req, R_req, F_req, O_req, P_req).

## Admission predicate

For a protected mutation:

ADMIT iff

A_req = A_current
AND G_req = G_current
AND R_req = R_current
AND F_req = F_current
AND O_req satisfies replay policy
AND P_req satisfies required policy/trust generation
AND Q = false.

This is a candidate formal predicate, not yet a verified theorem.

## Temporal safety property

If a request was stale at the protected effect boundary, it must not become admissible solely because of delay, restart, replay, or recovery.

Candidate:

STALE(request,t) AND EFFECT_ATTEMPT(request,t')
=> REJECT(request,t')

unless a new explicit authorization binding is created.

## Race R1 — rollover during request flight

T0 request issued under G7.
T1 authority advances to G8.
T2 request reaches resource.

Expected:
G7 request rejected.

Failure if:
resource accepts based only on issuance-time validity.

## Race R2 — read then rollover then effect

T0 strong read observes G7.
T1 authority advances to G8.
T2 effect attempts with G7.

Expected:
read does not authorize effect.

Required protection:
resource-side fence or atomic conditional effect boundary.

## Race R3 — crash after rollover

T0 resource at G8.
T1 crash.
T2 recovery restores state.
T3 G7 request arrives.

Expected:
G7 rejected.

Recovery must preserve or strictly supersede G8.

## Race R4 — crash after effect submission

T0 fence check passes.
T1 external request sent.
T2 process crashes before result recording.

Expected:
local state = UNKNOWN_EXTERNAL_RESULT.

No inference of success or failure without reconciliation evidence.

## Race R5 — duplicate after recovery

T0 O7 accepted.
T1 crash.
T2 O7 arrives again.

Expected:
replay policy recognizes O7 as prior identity.

This requires durable replay/effect state or an equivalent provider-side idempotency guarantee.

## Race R6 — incarnation collision

A1/G8 and A2/G8 exist.

Expected:
A1 request cannot be accepted merely because G8 matches.

Incarnation is part of authority identity.

## Race R7 — resource incarnation collision

R1/F8 and R2/F8 exist.

Expected:
request bound to R1 cannot mutate R2 merely because F8 matches.

## Race R8 — quarantine recovery

Resource enters Q=true because continuity is uncertain.

Expected:
protected effects remain blocked until explicit recovery establishes current state.

Q must not clear implicitly on process restart.

## Race R9 — watch gap

Consumer observes G8, misses G9, observes G10.

Expected:
G9 uncertainty causes revalidation.

No inference that G9 contained no revocation.

## Race R10 — stale snapshot

Snapshot S7 is cryptographically valid but authority is S8.

Expected:
S7 cannot become current without continuity proof.

## Liveness boundary

Safety and liveness must not be conflated.

Safety:
STALE_EFFECT_MUST_NOT_BE_ADMITTED.

Liveness:
VALID_EFFECT_SHOULD_EVENTUALLY_PROGRESS_WHEN_DEPENDENCIES_RECOVER.

A system may preserve safety by refusing progress during uncertainty.

## Failure interpretation

The predicate can fail because:

- authority state unknown;
- resource state unknown;
- incarnation mismatch;
- generation mismatch;
- replay conflict;
- policy/trust generation mismatch;
- quarantine;
- dependency currentness unknown.

UNKNOWN must not silently map to ALLOW for high-consequence effects.

## Formal attack result

The contract remains coherent under the tested symbolic races provided that all required state is authoritative/durable at the enforcement boundary.

However, this condition is itself a dependency and cannot be assumed universally.

The contract therefore yields a dependency:

FENCE_SAFETY
REQUIRES
DURABLE_AUTHORITY_STATE
AND DURABLE_RESOURCE_FENCE_STATE
AND RESOURCE_BOUNDARY_ENFORCEMENT
AND RECOVERY_CONTINUITY.

## Important non-theorem

We have NOT proven:

- implementation correctness;
- crash consistency of a concrete database;
- correctness of a concrete lease service;
- global linearizability across external providers;
- exactly-once external execution;
- absence of common-mode failure;
- complete formal verification.

This is a symbolic/adversarial design analysis only.

## Candidate temporal invariants

I1: G_current is monotonic within an authority incarnation.

I2: F_current never decreases within a resource incarnation.

I3: old authority incarnation cannot mutate a newer resource incarnation.

I4: quarantine blocks protected mutation.

I5: replay identity cannot be silently regenerated after recovery.

I6: unknown external result remains unknown until reconciliation.

I7: stale authorization cannot become current solely through elapsed time or network delay.

I8: restoration of an older state cannot silently restore authority.

## Counterexample boundary

If any enforcement resource can reset F_current to an older value without a protected continuity check, the stale-request safety property fails.

Therefore durability/continuity is not an implementation detail; it is part of the security claim.
