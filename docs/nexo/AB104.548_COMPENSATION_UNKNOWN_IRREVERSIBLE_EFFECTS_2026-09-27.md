# Nexo AB104.548 — Compensation, UNKNOWN outcomes, and irreversible effects

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
Compensation is a new external effect, not a database rollback. It is safe only when its preconditions, identity, authority, target state, and failure/recovery semantics are themselves defined. If the original effect is UNKNOWN, compensation may be premature, may duplicate recovery, or may be impossible. Some effects are non-compensable and require HOLD, explicit human decision, or a forward-recovery policy instead of pretending to restore the prior world state.

## Evidence
AWS describes Saga compensation as a separate transaction used for backward recovery after a prior local transaction, while also distinguishing forward recovery/retry from backward compensation. Microsoft’s Saga guidance identifies a pivot between compensable work and irreversible/noncompensable work; after that pivot, subsequent work must complete rather than assuming rollback is possible. Current distributed-systems guidance likewise emphasizes that compensation is application-specific rather than a mechanical inverse. citeturn0search0turn0search10turn0search6

## UNKNOWN original effect
If Effect E is UNKNOWN, blindly issuing compensation C is unsafe because:
1. E may never have happened -> C can create a new unwanted effect.
2. E may have happened once -> C may be the correct corrective action.
3. E may have happened partially -> C may only partially correct it.
4. E may have happened multiple times because the provider lacked idempotency -> one C may be insufficient.
5. The world may have changed since E -> C may now have different semantics.

Therefore:
`UNKNOWN(E) != PROOF(E_OCCURRED)`
and
`UNKNOWN(E) != PROOF(E_DID_NOT_OCCUR)`

Compensation requires a condition that distinguishes these cases, or an explicit policy accepting the residual uncertainty.

## Compensation capability classes
### C0 — No compensation
Effect is irreversible/non-reversible. Examples can include an already-sent message, physical action, or irreversible transfer depending on provider semantics. Nexo must not fabricate an undo. Use HOLD, human decision, or forward recovery.

### C1 — Exact inverse
Provider exposes a uniquely identified inverse that restores the relevant invariant, and the inverse is itself idempotent/reconcilable.

### C2 — Business compensation
The original state cannot be restored exactly, but a defined corrective action reaches an accepted business-safe state (e.g. refund/credit/cancel). This is not mathematical rollback.

### C3 — Forward recovery
Do not undo the prior effect; continue the workflow toward a safe terminal state. Useful after a noncompensable pivot.

### C4 — Manual/authority decision
Automated evidence is insufficient. Stop external progression and require an explicit decision with recorded rationale and authority.

## Compensation state machine
UNKNOWN(E)
-> RECONCILE(E)
-> [CONFIRMED_APPLIED | CONFIRMED_NOT_APPLIED | PARTIAL/AMBIGUOUS]

CONFIRMED_APPLIED -> COMPENSATION_PREPARED -> COMPENSATION_DISPATCH -> COMPENSATION_RECONCILE -> COMPENSATED/COMPENSATION_UNKNOWN

CONFIRMED_NOT_APPLIED -> no compensation; resume/retry only if authority and idempotency permit.

PARTIAL/AMBIGUOUS -> policy-specific recovery or HOLD.

Compensation itself can enter UNKNOWN and therefore needs its own EffectID, request digest, fence/authority context, durable intent, reconciliation, and possibly another compensation policy.

## No recursive fiction
Nexo must not assume infinite compensation always converges. A compensation graph can oscillate (E -> C -> counter-C -> ...), produce additional side effects, or become impossible after state changes. Recovery requires a bounded/declared terminal policy.

## Irreversible pivot
For a workflow containing compensable steps followed by a noncompensable step, the architecture should identify a pivot before execution. Microsoft explicitly models a pivot between compensable and irreversible/retryable portions. citeturn0search10

Candidate contract:
`PivotDeclared -> PreconditionsSatisfied -> IrreversibleEffect -> ForwardRecoveryOnly`

No automatic rollback claim is permitted after the pivot unless the provider independently exposes a verified corrective operation.

## Critical distinctions
- COMPENSATION != ROLLBACK
- UNKNOWN != APPLIED
- UNKNOWN != NOT_APPLIED
- COMPENSATION != PROOF_ORIGINAL_STATE_RESTORED
- REFUND != ERASE_CHARGE
- CANCEL_REQUEST != PHYSICAL_REVERSAL
- CORRECTIVE_ACTION != TIME_REVERSAL
- COMPENSATION_EFFECT != FREE_OPERATION
- COMPENSATION_UNKNOWN != ORIGINAL_FAILURE
- IRREVERSIBLE != AUTOMATICALLY_FORBIDDEN, but it requires stronger admission/authority semantics

## Nexo implication
Effect contracts need explicit `CompensationClass`, `CompensationEffectID`, `PivotStatus`, `ReconciliationMethod`, `TerminalRecoveryPolicy`, and whether a human/authority decision is required. For E3-E5 effects, an UNKNOWN original outcome must never trigger an automatic inverse unless the provider's semantics establish that the inverse is safe under the uncertainty.
