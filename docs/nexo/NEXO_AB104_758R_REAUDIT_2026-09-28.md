# NEXO AB104.758R — processChannelException / channel-invalidation re-audit

Date: 2026-09-28
Source baseline: Apache Kafka abf522e1ca5d7f4375baddc4da004da9fcb6e9ca

## Direct findings

`processChannelException(channelId, ...)` checks whether the channel is still open/closing, logs the failure, calls `close(channelId)`, then calls `processException(...)`. `close(channelId)` removes the channel from the selector, decrements connection quota, notifies disconnect listeners, and removes any pending `inflightResponses` entry while updating its metrics.

`processCompletedReceives()` catches a receive-processing Throwable and invokes `processChannelException`. If request construction has not completed (`header == null || req == null`), the receive buffer is explicitly closed before channel cleanup. Once a Request exists, the request has already been handed to `requestChannel`, so channel closure does not mean the already-enqueued Request is automatically erased from RequestChannel; the later lifecycle must reconcile it by connection identity/close state.

`processDisconnected()` separately removes any `inflightResponses` entry for the disconnected connection. This is a separate response-send lifecycle from request ingestion.

The processor main loop continues with `processCompletedSends()`, `processDisconnected()` and quota cleanup after `processCompletedReceives()` returns, while its outer Throwable guard prevents an ordinary unexpected exception from terminating the processor thread. Per-channel errors are intentionally isolated through `processChannelException`.

## Nexo-relevant boundary

Closing the transport/channel is a concrete local fence against further I/O on that channel, but it is NOT by itself equivalent to revoking every already-enqueued logical operation. A request already inserted into `RequestChannel` can exist beyond the socket close and requires its own identity/connection lifecycle handling. This maps directly to Nexo's distinction between transport invalidation, operation authority, queued work and external effect state.

`inflightResponses` is explicitly removed on close; request-side queued work is a different state domain.
