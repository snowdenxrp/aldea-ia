# Nexo AB104.563 — Epoch fencing and certificate authority

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
An old certificate can remain cryptographically valid evidence after a witness-set epoch changes. It must not remain authority-valid if the protocol epoch fence says the old configuration has been superseded.

Therefore distinguish:
- EVIDENCE_VALID: bytes/signatures/proof verify under historical rules.
- EPOCH_VALID: certificate belongs to an authority epoch currently admissible.
- PREDECESSOR_VALID: certificate links to the accepted continuity boundary.
- AUTHORITY_VALID: all protected admission predicates hold now.

HotStuff uses view/locking semantics so higher protocol progress does not by itself permit conflicting commits; RFC 9162 consistency proofs establish append-only consistency, not external authority. citeturn0search1turn0search25turn0search0

## Candidate epoch-fenced admission
1. Verify encoding/signatures.
2. Verify transition type and phase.
3. Verify predecessor anchor/digest.
4. Verify witness-set epoch and membership digest.
5. Verify quorum/intersection and independence for that epoch.
6. Verify authority epoch and continuity relation.
7. Compare with current trusted continuity boundary.
8. If historically valid but superseded, classify STALE_CERTIFICATE.
9. If two certificates from the same admissible epoch authorize incompatible successors, use the AB104.561 conflict procedure; never use timestamp or signature count as an ad-hoc tie-breaker.
10. If no unique authority-valid certificate remains, QUARANTINE/UNKNOWN.

## Critical distinctions
EPOCH_FENCE != HISTORICAL_ERASURE
VALID_SIGNATURE != CURRENT_AUTHORITY
VALID_CERTIFICATE != CURRENT_CERTIFICATE
HIGHER_EPOCH != PROOF_OF_EXECUTION
NEW_EPOCH != RETROACTIVE_CANCELLATION

## Recovery
The current epoch fence must itself be protected by the continuity/recovery boundary. A restored snapshot that rolls the epoch backward cannot safely reactivate old certificates. Durable consensus implementations likewise treat locked QC and view as safety-critical crash-recovery state. citeturn0search6

## Nexo consequence
Z1 should preserve historical certificates for audit/reconstruction while making current authority explicitly epoch-fenced. This separates: historical validity from present authorization.
