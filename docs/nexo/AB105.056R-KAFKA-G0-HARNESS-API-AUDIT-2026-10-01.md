## Harness API findings

1. KafkaClusterTestKit is instantiated with:
   new KafkaClusterTestKit.Builder(new TestKitNodes.Builder()...)
       .build()

2. The test-kit lifecycle used by Kafka tests is:
   cluster.format();
   cluster.startup();
   cluster.waitForReadyBrokers();

3. Non-combined topology is explicitly supported through:
   TestKitNodes.Builder.setCombined(false)
   with separate broker/controller node counts.

4. Per-server configuration is exposed by TestKitNodes.Builder.setPerServerProperties(...), allowing the target-broker-only wrapper configuration to be separated from controller configuration. This is the required direction for the frozen tuple; global authorizer configuration must NOT be used for the target-only wrapper.

5. KafkaClusterTestKit exposes broker/controller collections and broker internals, including broker authorizer plugin access. Existing Kafka tests also use:
   cluster.brokers().values().iterator().next().authorizerPlugin().get().get()

6. The Authorizer contract at current Kafka API shape is:
   configure(Map<String,?>)
   start(AuthorizerServerInfo)
   authorize(AuthorizableRequestContext,List<Action>)
   acls(AclBindingFilter)
   createAcls(...)
   deleteAcls(...)
   close()
   with optional/default methods such as aclCount()/authorizeByResourceType().
   The broker waits for authorizer start futures before accepting normal request traffic.

7. StandardAuthorizer is the built-in KRaft authorizer and stores ACL state in the metadata log. It can be wrapped/delegated while preserving the real authorization implementation.
