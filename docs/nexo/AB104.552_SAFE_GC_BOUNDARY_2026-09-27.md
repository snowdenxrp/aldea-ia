# Nexo AB104.552 — Safe-GC boundary for stale-message barriers

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
Garbage collection of tombstones/history is safe only after a monotonic coverage predicate is satisfied. Retention duration alone is not sufficient unless it is itself a justified upper bound for every delayed/replayed path relevant to the protected property.

Kafka explicitly treats delete.retention.ms as a bound on the time a consumer has to complete a read before tombstones may disappear; etcd similarly retains history for a configured time/revision window and then makes compacted revisions inaccessible. These systems demonstrate the general pattern: GC changes the evidence available to lagging readers, so the retention boundary is part of the protocol semantics.

## Safe-GC predicate
Candidate SAFE_GC(H) iff:
1. all producers/relays capable of delivering H are fenced from producing an admissible protected effect;
2. every relevant provider rejects H using durable incarnation/epoch/fence state, OR remaining uncertainty is explicitly quarantined;
3. maximum valid delayed-delivery/replay window has been covered;
4. provider idempotency/deduplication retention relevant to H has expired only after an independent replacement barrier exists;
5. target incarnation and authority epoch transitions are durable;
6. any required negative-history claim has archival coverage independent of the soon-to-be-collected artifact;
7. recovery paths cannot resurrect a pre-GC snapshot with authority to emit H;
8. the GC transition itself is durably ordered and auditable.

The predicate must be monotonic: once SAFE_GC(H) becomes true, later ordinary observations must not make it false. If an assumption becomes UNKNOWN (provider retention, recovery state, clock bound, archive availability, etc.), GC must stop or quarantine rather than infer safety.

## Evidence boundary
Kafka documents that consumers lagging beyond delete.retention.ms can miss tombstones; etcd documents that compacted revisions become inaccessible. Thus retention defines protocol semantics, not merely storage optimization.

## Adversarial case
T0 H created under I1/F1.
T1 H becomes UNKNOWN.
T2 I2/F2 activated.
T3 local tombstone becomes eligible for GC.
T4 paused relay resumes with H.
If provider checks I/F and rejects H, the old artifact may no longer be required for admission prevention. If provider does not, GC can destroy the only stale-message barrier. If historical nonoccurrence must later be established, the artifact may still be required even when admission prevention is guaranteed.

## Nexo rule
Separate three predicates:
- PREVENTION_COVERAGE — obsolete message cannot cause the protected effect.
- EVIDENCE_COVERAGE — required historical claims remain reconstructible.
- RECOVERY_COVERAGE — no valid recovery path can resurrect obsolete authority/message.

GC is permitted only when every predicate required by the protected property is satisfied.

## Critical distinctions
- RETENTION_EXPIRY != SAFE_GC
- GC_ELIGIBLE != GC_COMMITTED
- STALE_REJECTION != HISTORICAL_NONOCCURRENCE
- PROVIDER_HIGH_WATER_MARK != ARCHIVE_PROOF
- ARCHIVE_PROOF != REMOTE_PREVENTION
- CURRENT_ABSENCE != HISTORICAL_NONOCCURRENCE
- CLOCK_BOUND != DELIVERY_BOUND
- NORMAL_RECOVERY != PROOF_OF_NO_REPLAY
