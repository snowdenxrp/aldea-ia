# NEXO AB104.681 — Producer retry identity
Date: 2026-09-27
Status: RESEARCHED / NOT_IMPLEMENTED / NOT_EXECUTED

## Exact source finding
Current Apache Kafka ProducerBatch retains the encoded record in its MemoryRecordsBuilder. Retries increment the batch attempt counter and re-enqueue the same ProducerBatch. The batch's record key, value and headers are therefore not regenerated by the retry mechanism.

The source also explicitly documents a critical ambiguity: an inflight batch can expire and become FAILED even though the broker may have succeeded; a later successful ProduceResponse can arrive afterward. This directly reinforces the Nexo UNKNOWN boundary.

## Frozen base experiment
Use:
- one ProducerRecord created once;
- unique effectId never regenerated;
- retries=0 for the base response-loss experiment;
- acks=all;
- linger.ms=0;
- request.timeout.ms=1000;
- delivery.timeout.ms=3000.

Why retries=0:
- isolates one broker attempt;
- avoids a second Produce request changing the fault-counter surface;
- makes the experiment specifically about lost acknowledgement rather than retry recovery.

A separate later experiment can enable retries and test duplicate/idempotent behavior; it must not contaminate the base ambiguity experiment.

## Critical epistemic finding
ProducerBatch source confirms:
FAILED client state does not prove broker non-commit. Kafka explicitly permits a later broker success after a batch was already marked failed.

Therefore:
ProducerClientOutcome != BrokerRecordObservation.

## Status
VERIFIED:
- retry retains batch/record identity;
- failed batch can later correspond to broker success;
- retries=0 is the correct isolation boundary for the base experiment.
