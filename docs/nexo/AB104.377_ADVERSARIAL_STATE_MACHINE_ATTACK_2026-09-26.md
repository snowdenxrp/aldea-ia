## Fresh research
RFC 9110 warns against automatic retry of non-idempotent requests unless the client can establish idempotent semantics or detect that the original was not applied. ## New finding
The state machine needs a distinct distinction between:
- RETRY_ADMISSIBLE: a new attempt is permitted under current contract.
- RETRY_SAFE_EQUIVALENT: provider semantics establish that repeating the same EffectID cannot create a second logical effect.
These are not the same property.

## Candidate invariant
RETRY_ADMISSIBLE => current authorization + current recovery ownership + effect-class retry rule.
RETRY_SAFE_EQUIVALENT => RETRY_ADMISSIBLE + stable identity + provider-enforced equivalence/deduplication (or independently proven equivalent semantics).
