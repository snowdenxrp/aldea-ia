## Research question
How should Nexo model evidence independence without collapsing it into a misleading single trust score, and how do correlated failures defeat naive quorum/dual-control assumptions?

## External evidence
RFC 9334 separates Attester, Verifier, and Relying Party and explicitly treats trust anchors, appraisal policy, and freshness as distinct trust inputs. It also notes that combining roles is possible, meaning role labels alone do not guarantee independence. citeturn0search0

NIST's zero-trust architecture distinguishes the policy decision point from the policy enforcement point and describes enforcement at the protected-resource boundary. This reinforces that separate logical roles do not necessarily create independent failure domains. citeturn0search24turn0search2

## Failure-domain dimensions
Independence should be represented as a dependency graph, not one scalar score.

Candidate domains:
- TRUST_ROOT
- POLICY_SOURCE
- VERIFIER_RUNTIME
- TEST_HARNESS
- ADAPTER_CODE
- PROVIDER_CONTROL_PLANE
- PROVIDER_DATA_PLANE
- RESOURCE
- RESOURCE_FAILOVER
- GATEWAY
- NETWORK_PATH
- OBSERVER
- TIME_SOURCE
- CONFIGURATION_STORE
- KEY_MANAGEMENT
- DEPLOYMENT_PIPELINE
- OPERATOR/ADMINISTRATIVE_DOMAIN

A claim's evidence is independent only with respect to the failure domains relevant to that claim.

## Dependency graph
Candidate:
EVIDENCE_NODE
  -> DEPENDS_ON -> DOMAIN_NODE
  -> PRODUCED_BY -> SOURCE_NODE
  -> VERIFIED_BY -> VERIFIER_NODE
  -> APPRAISED_UNDER -> POLICY_NODE
  -> BINDS_TO -> RESOURCE/INCARNATION

A promotion claim computes closure over dependencies:
CLAIM_DEPENDENCY_CLOSURE = all domains that can invalidate the claim.

Two evidence nodes sharing a safety-relevant domain are correlated even if they have different logs, processes, or vendors.

## Why naive quorum fails

### Attack 1 — 3-of-5 all share one provider
Five verifiers independently inspect provider evidence, but all depend on the same provider control plane.
Provider compromise can make all five agree incorrectly.
Result: count=5, independent domains=1.

### Attack 2 — gateway + provider collusion
Gateway evidence, provider telemetry, and gateway verifier all share the same authority path.
A stale-fence failure can be consistently hidden.
Result: apparent quorum without independent enforcement.

### Attack 3 — two verifiers, one policy source
Verifier A and B run independently, but both consume a compromised appraisal policy.
Both can produce matching but invalid results.
Result: verifier independence does not compensate for policy-source common mode.

### Attack 4 — independent observers, common time source
A trusted-time failure shifts all observations or freshness decisions.
Result: multiple observations share TIME_SOURCE dependency.

### Attack 5 — separate adapters, shared deployment artifact
Two adapters are independently tested but both derive from a compromised build artifact.
Result: code-path independence is overstated.

### Attack 6 — failover replicas share state corruption
Active and standby providers are operationally separate but share a corrupted fence high-water mark.
Result: failover does not provide independent evidence for DFS/XF.

### Attack 7 — provider and observer share the same telemetry plane
Observer appears external but receives only provider-controlled telemetry.
Result: observation independence is false for claims about provider execution.

## Claim-specific independence matrix

| Claim | Critical domains that should not all be common-mode |
|---|---|
| Target conditional | adapter + resource mutation path + relevant provider state |
| Authority fence | authority source + fence enforcement boundary + resource state |
| Durable fence | resource persistence + failover path + fence HWM |
| Idempotency | effect identity store + mutation path + retry path |
| Durable intent | intent store + release path |
| ACK confirmation | provider execution + acknowledgement path + identity binding |
| Reconciliation | provider state + independent observation/query path where required |
| Cancellation | cancellation path + acceptance path |
| Reversal | original effect state + compensation path |
| Failover preservation | active path + standby/failover state + persistence |
| Multi-resource composition | every relevant participant + coordination/reconciliation path |

This is not a numeric trust score; it is a dependency coverage requirement.

## Dual-control hardening
Dual-control should require:
1. distinct administrative authority where appropriate;
2. distinct verifier runtime;
3. independent evidence acquisition path;
4. no unresolved shared critical domain;
5. independent policy integrity or independently verified policy digest;
6. separate revocation/invalidity detection where practical.

If A and B share a critical domain, the pair should be recorded as correlated rather than counted twice.

## Quorum rule
Candidate:
A promotion quorum is valid only if:
- required participant coverage is complete;
- required independent failure domains are covered;
- no single unresolved common-mode domain can falsify every supporting result;
- each result is bound to the same claim scope/version/incarnation;
- contradictions are explicitly handled.

Therefore:
QUORUM = COVERAGE + INDEPENDENCE + CONSISTENCY
not simply N-of-M.

## Emergency verifier outage
If required independent evidence cannot be obtained:
- retain existing historical results;
- do not create new high-consequence validation;
- if an already-validated capability crosses its freshness/validity boundary, move to UNKNOWN/DEGRADED;
- use HOLD/RESTRICT for effects whose safety claim depends on unavailable validation;
- never manufacture independence from repeated cached/provider evidence.

## Mixed direct/gateway paths
For a participant protected directly and another through a gateway:
- direct participant closure includes resource fence domains;
- gateway participant closure includes gateway, mapping store, downstream enforcement, and downstream failover domains;
- global claim requires coverage across both closures.

A gateway can reduce integration complexity but does not erase downstream dependencies.
