# Nexo AB104.557 — Witness rotation and anchor succession

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Evidence
Raft's joint-consensus design avoids an unsafe membership transition by requiring agreement from both old and new configurations during the transition; neither side can make unilateral decisions until the new configuration is committed. citeturn0search26turn0search27 RFC 9162's consistency proofs provide an analogous historical-continuity check between log tree heads: a later head can be accepted as consistent with an earlier head only when the proof verifies. citeturn0search3

## Finding
Witness rotation must be treated as a protected configuration transition, not as replacement of a list. Directly switching from W_old to W_new creates a rollback window: a restored system may choose the old set while another system accepts the new set.

Candidate safe sequence:
W_OLD_VALID
-> W_JOINT_PREPARED
-> W_JOINT_ACTIVE
-> ANCHOR_OBSERVED_BY_OLD_AND_NEW
-> W_NEW_ACTIVE
-> W_OLD_DEPRECATED

During the joint interval, acceptance of a new ContinuityAnchor requires the applicable threshold/independence conditions of BOTH old and new witness sets. The exact quorum rule remains claim- and threat-model-specific; quorum count alone is not an independence proof.

## Anchor succession
A new anchor must cryptographically bind to the previous accepted anchor (or to an independently witnessed continuity checkpoint) and include:
- previous anchor digest;
- new anchor digest;
- witness-set epoch;
- authority epoch;
- monotonic continuity value;
- state/incarnation summary;
- transition identifier.

A witness should attest that it observed the succession, not that it has execution authority.

## Crash cases
Crash before W_JOINT_ACTIVE: old set remains authoritative; new set is merely prepared.
Crash during joint state: neither set may unilaterally authorize the final succession.
Crash after W_NEW_ACTIVE: old witnesses cannot resurrect the old configuration as current without a new protected transition.
Ambiguous activation: quarantine rather than selecting whichever set is locally available.

## Compromise cases
If W_old is compromised before rotation, allowing W_old alone to approve W_new defeats the purpose of rotation. If W_new is compromised before activation, it must not become authoritative merely because it possesses the new configuration. The transition needs an independent continuity proof and the required authority/independence policy.

## Critical distinctions
WITNESS_COUNT != INDEPENDENCE
WITNESS_SIGNATURE != EXECUTION_AUTHORITY
W_NEW_PREPARED != W_NEW_ACTIVE
JOINT_OBSERVED != JOINT_AUTHORIZED
NEW_WITNESS_SET != NEW_TRUST_BASIS
ROTATION != RETROACTIVE_ERASURE
ANCHOR_SUCCESSION != EXTERNAL_EFFECT_RECONCILIATION

## Nexo consequence
Witness-set epoch is a first-class protected version. Anchor rotation and witness rotation should be coupled through explicit transition records, so a restored or partitioned node cannot select an older witness set merely because it has a locally valid signature.
