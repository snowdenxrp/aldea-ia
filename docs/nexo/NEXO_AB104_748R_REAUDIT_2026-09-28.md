Date: 2026-09-28

## Direct findings

OffsetForLeaderEpochClientTest uses ConsumerNetworkClient + MockClient and `client.prepareResponse(resp)`. Its five tests only inject normal responses through the mock path. The file contains no independently chosen response correlation ID and no correlation-mismatch assertion.

NetworkClientTest provides a lower-level raw-wire mechanism: a real NetworkClient creates a real ClientRequest and exposes its actual correlationId; RequestTestUtils.serializeResponseWithHeader(response, version, correlationId) can encode a chosen response correlation ID; MockSelector.completeReceive(new NetworkReceive(...)) injects the serialized response; NetworkClient.poll() processes it. Existing tests demonstrate this mechanism with matching correlation IDs.

The inspected NetworkClientTest source does not contain a dedicated OFLE correlation-mismatch test. Its generic simple request/response path uses ProduceResponse, not OFLE. Therefore the mechanism is directly evidenced, but OFLE-specific mismatch execution remains unproven.

## Addendum — direct source recheck
The current recheck confirms the original R finding. NetworkClientTest's `checkSimpleRequestResponse` serializes the response with `request.correlationId()` and injects it via `MockSelector.completeReceive`; this is matching-correlation execution only. A repository search for a dedicated `CorrelationIdMismatchException` assertion in NetworkClientTest returned no result. RequestTestUtils does permit an independently selected correlation ID, so the missing evidence is execution, not construction capability.

Final classification remains: OFLE mismatch EXECUTED=NO; direct NetworkClient mismatch assertion=NO; raw injection mechanism=YES; arbitrary correlation construction=YES.
