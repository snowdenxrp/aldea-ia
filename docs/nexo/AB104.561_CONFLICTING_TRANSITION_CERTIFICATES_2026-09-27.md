# Nexo AB104.561 — Conflicting transition certificates

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Evidence
BFT consensus protocols rely on quorum intersection and protocol-defined certificate rules rather than arbitrary certificate selection. HotStuff is a concrete partially synchronous BFT design built around quorum certificates; generalized-quorum research shows that trust assumptions can require structures more expressive than a simple numeric threshold. ## Finding
When two transition certificates conflict, Nexo must never select one merely because it has:
- more signatures;
- newer wall-clock time;
- a locally preferred witness;
- a larger numeric quorum without checking independence;
- a newer certificate that lacks valid predecessor binding.

Instead, classify both certificates against the same deterministic predicate.

## Candidate deterministic classification
For each certificate C:
A = correct witness-set epoch
B = valid phase transition
C = predecessor anchor binding
D = continuity monotonicity
E = required quorum/intersection
F = dependency closure valid
G = recovery-anchor compatibility
H = no unresolved higher/equal-authority conflict

If all required predicates hold, C is AUTHORITY_CANDIDATE. If any mandatory predicate fails, C is REJECTED_EVIDENCE (with reason), not an alternate authority.

If two candidates both satisfy the predicates but represent incompatible successor histories, the protocol's safety invariant has encountered a conflicting valid certificate. Do not invent a tie-breaker. Enter QUARANTINED / UNKNOWN unless the protocol has a previously specified deterministic ordering rule that is itself authority-safe.

## Why "newer wins" is unsafe
A later timestamp does not establish causal authority, especially under clock skew, partition, rollback, or Byzantine timestamp manipulation. A higher continuity counter is useful only when that counter is protected by an accepted chain/anchor. A higher certificate sequence alone is not proof that its predecessor was validly committed.

## Byzantine equivocation
If the same witness signs incompatible statements for the same transition context, record the equivocation evidence. This may invalidate the witness for the affected transition, but it does not automatically prove which competing certificate is correct.

## Recovery rule
1. Freeze protected authority.
2. Preserve both conflicting certificates and their evidence.
3. Deterministically validate each certificate.
4. Build dependency/quorum intersection analysis.
5. If exactly one candidate is uniquely justified, admit that candidate.
6. If zero candidates are justified, remain QUARANTINED.
7. If multiple incompatible candidates remain justified, remain QUARANTINED/UNKNOWN and require the predefined recovery authority or new jointly authorized transition.
8. Never discard the losing certificate before recording why it lost.

## Claim-specific outcome
A conflict may be harmless for one claim and fatal for another. Therefore the conflict result must be bound to the protected property and threat model. A certificate can be valid evidence while still insufficient for authority.

## Critical distinctions
CERTIFICATE_COUNT != AUTHORITY
NEWER_TIMESTAMP != NEWER_AUTHORITY
HIGHER_COUNTER != VALID_COMMITMENT
VALID_SIGNATURE != VALID_SUCCESSOR
VALID_CERTIFICATE != UNIQUE_HISTORY
EQUIVOCATION != PROOF_OF_WHICH_SIDE_IS_TRUE
CONFLICT != FAILURE
CONFLICT != SAFE_TIE

## Nexo consequence
Nexo should have an explicit CONFLICTED_TRANSITION state and a deterministic validation function. The safe default for unresolved incompatible authority candidates is QUARANTINED/UNKNOWN, not local preference.
