## Fresh primary evidence
RFC 9334 defines Evidence as Claims generated by an Attester and appraised by a Verifier; the Relying Party separately applies an appraisal policy to Attestation Results. Freshness is an appraisal decision and has an unavoidable race with state changes after evidence generation. citeturn0search0
NIST SP 800-160 defines assurance as justified confidence in claims based on objective evidence and emphasizes that evidence must be relevant, accurate, credible, and sufficient for reasoned conclusions. citeturn0search3

## Integrated evidence object
OBSERVATION
  -> CLAIM_SET
  -> SOURCE_PROVENANCE
  -> FRESHNESS_CONTEXT
  -> COVERAGE_SCOPE
  -> DEPENDENCY_GRAPH
  -> APPRAISAL_RESULT

These dimensions are independent and must not be collapsed into one confidence number.

## Three-dimensional appraisal
1. FRESHNESS
   FRESH / STALE / UNKNOWN_FRESHNESS

2. COMPATIBILITY
   COMPATIBLE / STATE_TRANSITION / CONFLICT / UNKNOWN

3. DEPENDENCY
   INDEPENDENT / CORRELATED / UNKNOWN_INDEPENDENCE

A claim can therefore be:
FRESH + CONFLICTING + INDEPENDENT
or
FRESH + COMPATIBLE + UNKNOWN_INDEPENDENCE
or
STALE + COMPATIBLE + CORRELATED.

No dimension may automatically upgrade another.

## Adversarial integration
Case 1: two fresh observations disagree and share a root -> CONFLICT + CORRELATED.
Case 2: two fresh observations disagree with independently established roots -> CONFLICT + INDEPENDENT.
Case 3: fresh observation has unknown dependency -> FRESH + UNKNOWN_INDEPENDENCE.
Case 4: stale observation agrees with a fresh observation -> compatibility may be established, but stale evidence remains stale.
Case 5: stale observation conflicts with fresh observation -> preserve both; consuming policy decides whether the stale record is relevant.
Case 6: dependency graph is partial but all decision-relevant roots are established -> bounded assurance may remain available.
Case 7: dependency graph is partial and a missing root could invalidate the decision -> UNKNOWN/STOP.
Case 8: reconciliation establishes a state transition -> it does not establish the cause.
Case 9: fresh evidence is authoritative for one scope but not another -> scope must remain explicit.
Case 10: multiple records derive from one event -> multiplicity cannot be counted as independent corroboration.

## Claim/Decision boundary
The resulting generic flow is:
EVIDENCE -> APPRAISAL -> CLAIM_STATE -> DECISION_INPUT

Appraisal produces a bounded result for the decision; it does not rewrite the evidence.
A Decision Contract must declare what freshness, compatibility, coverage, and independence states it requires.
If those requirements are unmet, the result is UNKNOWN/STOP for the affected consequential decision, while unrelated observation/collection can continue.
