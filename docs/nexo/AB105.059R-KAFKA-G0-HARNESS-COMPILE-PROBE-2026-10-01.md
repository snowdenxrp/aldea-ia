## New pinned-source findings

1. KafkaClusterTestKit.Builder.createNodeConfig() applies global configProps first and then the broker node propertyOverrides. Therefore a target-only broker override of ServerConfigs.AUTHORIZER_CLASS_NAME_CONFIG is mechanically supported without changing the controller authorizer.
2. Pinned KRaftClusterTest uses server-id 0 for broker nodes and controller ids beginning at 3000 in the demonstrated non-combined TestKit layout. This gives a concrete target broker id for the temporary harness, but the harness must still assert actual node maps at runtime rather than assuming an id without checking.
3. KafkaClusterTestKit's built-in SASL/PLAIN test support creates an admin principal and a separate test user in its JAAS context. When SASL/PLAIN is used, TestKit sets StandardAuthorizer and configures the admin principal as a super-user unless overridden.
4. This resolves an important harness-design constraint: use SASL/PLAIN so the administrative DeleteAcls client can be a distinct authenticated super-user while the Produce client uses the non-superuser test user. Do not use PLAINTEXT with one anonymous principal for both roles.
5. The planned G0 producer should retain a topic DESCRIBE permission as auxiliary setup if needed for metadata discovery, while the target WRITE permission remains the ACL deleted by D0. This allows D1 to reach the Produce authorization decision while still being denied WRITE.
6. Kafka's documented KRaft authorization model confirms broker-forwarded admin requests are authorized on the controller using the forwarded client principal; this supports treating Admin DeleteAcls as the control-plane boundary rather than as a direct broker-local ACL mutation. See Apache Kafka authorization documentation: KRaft principal forwarding and controller authorization. citeturn0search2
