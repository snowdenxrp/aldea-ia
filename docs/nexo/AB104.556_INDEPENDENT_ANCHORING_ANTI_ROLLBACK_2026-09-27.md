# Nexo AB104.556 — Independent anchoring and anti-rollback

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Evidence
etcd recovery shows that a restored snapshot can have an older revision and therefore requires an explicit revision bump/compaction strategy; restore also creates a new logical cluster identity. RFC 9162 provides a concrete independent-observation pattern: signed tree heads plus consistency proofs allow observers to detect an inconsistent log view, while the specification explicitly treats auditing as a separate function from the log itself. citeturn0search0turn0search1

## Finding
An anti-rollback anchor needs two logically separate properties:
1. monotonic continuity: a later trusted anchor must not be accepted as older than the last accepted boundary;
2. independence: the entity that stores/attests the anchor must not be completely controlled by the same failure/compromise domain whose rollback is being detected.

A second copy in the same trust domain is replication, not independence.

## Minimum candidate
ContinuityAnchor = {
  AnchorID,
  AuthorityEpoch,
  MonotonicCounter,
  StateDigest,
  RecoveryGeneration,
  IncarnationSummary,
  FenceHighWaterSummary,
  DependencySnapshotDigest,

  Signature/attestation,
  PreviousAnchorDigest
}

Independent witness record = {
  AnchorDigest,
  WitnessEpoch,
  ObservedAt,
  PreviousAnchorDigest,
  WitnessSignature
}

The witness should attest to observation/continuity, not automatically become execution authority.

## Rotation
Safe anchor rotation requires an explicit transition:
OLD_ANCHOR_VALID -> NEW_ANCHOR_PREPARED -> WITNESSED -> NEW_ANCHOR_ACTIVE -> OLD_ANCHOR_DEPRECATED

The new anchor must reference the previous anchor (or an independently witnessed chain) and must be rejected if its predecessor/epoch relationship cannot be established.

Crash between PREPARED and ACTIVE must not make the new anchor authoritative. Crash after ACTIVE must not allow fallback to the old anchor as current authority.

## Compromise
If the anchor store and witness share the same compromise domain, a compromised actor may present a consistent-looking rollback to both. Therefore Nexo's independence claim must be failure-domain based, not copy-count based.

If independent witness coverage is unavailable, the anchor may still provide local continuity evidence, but the stronger anti-rollback claim becomes UNKNOWN.

## Critical distinctions
COPY_COUNT != INDEPENDENCE
ANCHOR_SIGNATURE != ROLLBACK_PROOF
WITNESS_ATTESTATION != EXECUTION_AUTHORITY
CONSISTENCY_PROOF != WORLD_TRUTH
NEW_ANCHOR != NEW_TRUST_BASIS
ROTATION != RETROACTIVE_ERASURE
LOCAL_MONOTONICITY != CROSS_DOMAIN_ANTI_ROLLBACK

## Nexo consequence
For protected continuity, use an anchor chain plus independent witness observation where the threat model requires rollback detection. The witness set itself needs an epoch and its own anti-rollback/re-enrollment lifecycle. Anchor rotation must be a protected transition and cannot silently replace the prior trust basis.
