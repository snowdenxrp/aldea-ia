# AB104.494 — quorum-certificate binding to membership epoch/configuration

## Research
Concrete Raft/etcd implementations bind configuration changes to the replicated log/state machine rather than treating membership as an independent mutable parameter. etcd rejects overlapping uncommitted membership changes and applies a configuration change only at its defined state-machine point. ## Nexo certificate binding
A quorum certificate must be scoped to the exact authority configuration under which it was produced. Candidate binding:

`QC = {Effect/DecisionDigest, MembershipEpoch, MembershipDigest, TrustBasisEpoch, ThresholdProfile, CheckpointDigest, ProtocolVersion, View/Revision, SignerSetCommitment, Signature, IssuedAt}`

The verifier must validate the certificate against the currently authorized epoch and configuration digest before using it for current authority. A cryptographically valid certificate from an older epoch remains historical evidence but cannot authorize a current transition after the fence.

## Replay defenses
Required checks:
1. `MembershipEpoch == CurrentMembershipEpoch` for current authorization;
2. `MembershipDigest == CurrentMembershipDigest`;
3. `TrustBasisEpoch == CurrentTrustBasisEpoch`;
4. `SignerSetCommitment` matches the configuration used to evaluate the quorum;
5. `ThresholdProfile` is the authorized profile for that epoch;
6. `CheckpointDigest` is consistent with the accepted checkpoint chain;
7. certificate revision/view is not stale or superseded;
8. signer status is valid at the relevant epoch.

If a historical certificate must be used during recovery, it must be explicitly classified as historical evidence and must not silently promote to current authority.

## Critical distinction
`VALID_SIGNATURE != VALID_CURRENT_QUORUM_CERTIFICATE`
`VALID_QC_OLD_EPOCH != CURRENT_AUTHORITY`
`SIGNER_SET_COUNT != CONFIGURATION_BINDING`
`MEMBERSHIP_DIGEST != TRUST_BASIS_DIGEST`
`CHECKPOINT_DIGEST != AUTHORIZATION_DIGEST`

## Configuration transition
The membership digest itself should be included in the durable transition record. A transition therefore binds:
`OldEpoch + OldMembershipDigest + NewEpoch + NewMembershipDigest + OldThreshold + NewThreshold + ParentCheckpoint + TrustBasisTransition + ActivationRevision`.

This prevents an attacker from taking a valid certificate from one configuration and replaying it under another configuration with the same apparent member names or keys.

## Identity reuse
The etcd implementation's permanent removal of member IDs is concrete evidence for the stronger Nexo rule that identity reuse must not silently preserve authority lineage. A replacement witness should receive a new identity/incarnation and enter through the protected enrollment path.

## Status
Research complete. The result is a certificate-binding contract candidate, not a formal proof. Exact cryptographic encoding, canonical serialization, key-epoch semantics, and recovery use of historical certificates remain open. No implementation or formal verification performed.
