# AB104.520 — receipt archival, replay resistance, and evidence continuity

## Evidence
RFC 9162 requires a transparency log to retain the data needed to audit an accepted entry and supports cryptographic inclusion/consistency proofs; however, the log itself does not establish the truth of the underlying claim. citeturn0search0turn0search4 NIST SP 800-57 treats archival as a lifecycle concern and notes that verification keys may need to be retained for as long as signed data must remain verifiable. citeturn0search24turn0search6 RFC 3126 provides a concrete long-term-signature pattern in which validation material is preserved together with signed data and later archive timestamps can cover the complete archived validation material. citeturn0search5

## Core finding
A provider receipt that is useful today is not automatically sufficient evidence for future recovery. Nexo must preserve enough material to reconstruct the exact claim, verify its authenticity under the relevant historical trust basis, establish its temporal/epoch context, and detect substitution or replay.

Candidate archive object:
`ArchivedEffectEvidence = {OriginalReceiptBytes, ReceiptDigest, OperationID, EffectID, RequestDigest, TargetIdentity, TargetIncarnation, ProviderRevision, ProviderScope, AuthorityEpoch, FenceRevision, TrustBasisEpoch, VerificationKeyRef, VerificationMetadata, ObservedAt, EvidenceValidity, ArchiveSequence, ArchiveIntegrityProof}`

## Three distinct properties
`PRESERVATION != AUTHENTICITY != CURRENT_VALIDITY`.

- Preservation: the original evidence bytes/digest remain recoverable.
- Authenticity: the evidence can still be cryptographically verified against the appropriate historical trust basis.
- Current validity: the evidence remains admissible for the present claim/policy.

A historical receipt may remain authentic while no longer authorizing a new effect.

## Replay/substitution defense
Every archived receipt must remain bound to the original semantic context:
`EffectID + RequestDigest + TargetIncarnation + ProviderScope + AuthorityEpoch + FenceRevision`.

A valid signature on a receipt with a different context must not be accepted as evidence for the original effect.

`VALID_SIGNATURE != VALID_RECEIPT_FOR_THIS_OPERATION`
`VALID_RECEIPT != CURRENT_AUTHORITY`
`SAME_BYTES != SAME_SEMANTIC_CONTEXT` if context binding is external to the signed bytes.

Canonical serialization/domain separation must bind the receipt to its evidence class and protocol version. Translation or normalization creates a new derived statement rather than silently replacing the original evidence.

## Archive integrity
An archive may use append-only logs, Merkle commitments, signed checkpoints, or equivalent mechanisms. RFC 9162 demonstrates that inclusion and consistency proofs can make historical log membership and append-only evolution auditable. citeturn0search0 But:
`INCLUSION_PROOF != CLAIM_TRUTH`
`CONSISTENCY_PROOF != AUTHORIZATION`
`APPEND_ONLY != CURRENT_STATE`.

The archive therefore preserves evidence; it does not become an external-world authority merely because it is append-only.

## Key lifecycle
Long-term evidence depends on historical verification keys/trust anchors remaining available or on a formally preserved replacement validation path. NIST explicitly treats archival/retention of public verification keys as a lifecycle requirement when signed data must remain verifiable. citeturn0search24turn0search6 If a trust key is rotated or revoked, Nexo must retain enough historical metadata to distinguish:
- evidence signed while the key was valid;
- evidence generated after revocation;
- evidence whose verification status is now indeterminate.

`KEY_ROTATION != HISTORICAL_EVIDENCE_ERASURE`
`KEY_REVOCATION != RETROACTIVE_INVALIDATION_OF_PAST_FACT`

## Archive timestamp limitation
An archive timestamp can strengthen evidence that a particular evidence package existed at or before a given archival event. RFC 3126 shows this pattern for long-term signatures. citeturn0search5 It does not by itself prove that the underlying external effect occurred at that time; it proves the archived evidence package existed then under the timestamping authority's semantics.

`ARCHIVE_TIMESTAMP != EFFECT_TIME`
`ARCHIVE_TIMESTAMP != WORLD_TRUTH`

## Minimum archival transition
`LIVE_RECEIPT`
→ `RECEIPT_VALIDATED`
→ `CONTEXT_BOUND`
→ `ARCHIVE_COMMITTED`
→ `ARCHIVE_INTEGRITY_CHECKED`
→ `RECOVERABLE_EVIDENCE`

A receipt is not considered durably preserved merely because a hash or database pointer was stored. The original bytes or an independently reconstructible authenticated representation must remain available according to the retention class.

## Recovery after provider pruning
If the provider later prunes its operation record, Nexo may still preserve the original receipt and its verification material. This can preserve the historical provider-scope claim, but it cannot manufacture provider state that was never included in the original receipt.

`PROVIDER_PRUNING != HISTORICAL_ERASURE` when Nexo has preserved sufficient evidence.

Conversely:
`PROVIDER_PRUNING + NO_LOCAL_EVIDENCE => CLAIM_MAY_BECOME_UNKNOWN`.

## Archive compromise
If an archive is compromised, conflicting evidence packages must not be silently merged. Preserve original digests/checkpoints, identify the affected archive epoch, and require an independent trust transition before treating repaired evidence as authoritative.

`ARCHIVE_COMPROMISE => EVIDENCE_TRUST_REASSESSMENT`
`REPAIRED_ARCHIVE != AUTOMATIC_HISTORICAL_TRUTH`

## Invariants
- `PRESERVATION != AUTHENTICITY != CURRENT_VALIDITY`
- `VALID_SIGNATURE != VALID_RECEIPT_FOR_THIS_OPERATION`
- `INCLUSION_PROOF != CLAIM_TRUTH`
- `CONSISTENCY_PROOF != AUTHORIZATION`
- `APPEND_ONLY != CURRENT_STATE`
- `KEY_ROTATION != HISTORICAL_EVIDENCE_ERASURE`
- `KEY_REVOCATION != RETROACTIVE_INVALIDATION_OF_PAST_FACT`
- `ARCHIVE_TIMESTAMP != EFFECT_TIME`
- `ARCHIVE_TIMESTAMP != WORLD_TRUTH`
- `RECEIPT_REFERENCE != PRESERVED_RECEIPT`
- `PROVIDER_PRUNING + NO_LOCAL_EVIDENCE => UNKNOWN_OR_QUARANTINE`
- `ARCHIVE_COMPROMISE => EVIDENCE_TRUST_REASSESSMENT`

## Status
Research complete. Nexo's durable evidence layer must preserve original receipt material, semantic context, historical verification basis, archive integrity, and retention metadata. Cryptographic/log archival strengthens reconstructability but never promotes historical evidence into current authority or external-world truth.

No implementation or formal verification performed.
