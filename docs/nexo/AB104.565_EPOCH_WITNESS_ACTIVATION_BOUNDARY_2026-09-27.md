# Nexo AB104.565 — Epoch and witness-set activation boundary

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Evidence
Raft joint consensus does not switch directly from old to new membership. The transitional configuration requires agreement from both old and new configurations, then the new configuration is committed. This prevents either side from making unilateral decisions during the transition. CCF similarly makes reconfiguration commits require quorum acknowledgement in both the previous and new configurations. citeturn0search26turn0search0turn0search11

## Finding
For Nexo, witness-set activation and authority-epoch activation cannot be treated as two unrelated local switches if either can authorize protected transitions. A gap can create a state where the new epoch is current but the intended witness basis is not authoritative, or the new witness set is accepted while the old epoch fence still permits old certificates.

The safe design is one protected semantic activation boundary, or an explicitly defined joint transitional state whose authority predicate requires both old and new configurations as specified.

## Candidate state machine
OLD_ACTIVE -> JOINT_PREPARED -> JOINT_ACTIVE -> NEW_PREPARED -> NEW_ACTIVE -> OLD_DEPRECATED

JOINT_ACTIVE is an authority state: protected decisions require the jointly specified evidence from both configurations.

## Why separate local commits are dangerous
If E1 commits before W1, a node may accept an E1 certificate without the intended independent witness basis. If W1 commits before E1, a node may accept W1 signatures while still treating E0 certificates as current. A crash between durable records can make recovery reconstruct different authority states.

A local transaction boundary is insufficient when two records participate in the same authority claim.

## Important nuance
Epoch and witness configuration need not occupy one physical database row. What must be atomic is the semantic authority transition: recovery needs one unambiguous rule determining which combined configuration is authorized. This can be one consensus-log entry, a joint-consensus certificate binding old/new sets and epoch transition, or an equivalent protected transition with an explicit linearization point. Sequentially writing two fields does not provide this property.

## Crash semantics
Before the protected activation boundary: old authority remains. During JOINT_ACTIVE: neither side may act unilaterally outside the joint rule. After NEW_ACTIVE: old epoch/certificate authority is fenced. If recovery cannot prove which boundary committed, protected authority becomes UNKNOWN/QUARANTINED.

## Critical distinctions
PHYSICAL_ATOMICITY != SEMANTIC_ATOMICITY
EPOCH_COMMIT != WITNESS_COMMIT
NEW_WITNESS != NEW_AUTHORITY
JOINT_PREPARED != JOINT_AUTHORITY
LOCAL_COMMIT != GLOBAL_AUTHORITY
NEW_EPOCH != NEW_TRUST_BASIS

## Nexo consequence
Treat AuthorityEpoch, WitnessSetEpoch, MembershipDigest and ContinuityAnchor as one authority-relevant configuration snapshot. Its activation requires an explicit protected transition and durable recovery semantics. Independent local activation of components must never create authority.
