# Nexo AB104.541 — Provider fencing high-water mark loss, rollback, and recovery

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
Provider-side fencing is only safe if the provider's remembered high-water mark survives the failure modes that could otherwise make an old token acceptable again. A provider restore that lowers its remembered fence can resurrect stale writers even when Nexo's own authority history remains correct.

## Evidence
etcd documents that restoring an older snapshot can make revisions appear to go backwards and recommends revision bumps to prevent decreasing revisions after restore. Kubernetes uses resourceVersion for optimistic concurrency and rejects updates based on stale versions. Current etcd recovery also changes cluster/member identity during snapshot restoration. These facts demonstrate that recovery can change ordering context and that stale caches/writers require explicit invalidation. citeturn0search1turn0search0turn0search11

A concrete 2026 fenced-lock implementation explicitly requires the downstream resource to remember the highest accepted fencing token and warns that restoring/replacing the coordination cluster can invalidate token-order assumptions unless a durable recovery epoch or equivalent revision bump is enforced. This is implementation evidence, not a universal standard. citeturn0search2

## Candidate provider invariant
For a fencing scope S:
ACCEPT(token) only if token is valid for the current provider authority epoch AND token >= HighWaterMark[S].
On successful acceptance:
HighWaterMark[S] := token atomically with the protected mutation.

The high-water mark must not decrease across ordinary crash recovery, failover, snapshot restore, or storage replacement.

## Recovery cases
1. Provider restarts with intact high-water mark: continue normally.
2. Provider restores an older snapshot: do not resume external admission until ordering continuity is re-established.
3. Provider loses the high-water mark completely: fencing protection is UNKNOWN; enter quarantine/HOLD.
4. Provider starts a new storage identity: require a new provider authority epoch and explicit rebinding; old tokens must not become valid by numeric coincidence.
5. Nexo advances its fence while provider is unavailable: on return, reconcile provider high-water mark before allowing new effects.

## Recovery mechanisms
Candidate mechanisms include:
- durable monotonic high-water mark with crash-consistent storage;
- hardware/independent trusted persistence when the provider's storage is itself inside the trust boundary;
- provider epoch/generation that is changed during destructive restore;
- revision bump that is provably above all tokens that could still arrive late;
- quarantine until all previously issued tokens are provably stale or the provider is moved to a new non-overlapping namespace.

No mechanism should claim safety merely because the restored value is 'higher than the local snapshot'; the bound must cover delayed old tokens that may still be in flight.

## Cross-domain requirement
Nexo cannot infer provider high-water-mark continuity from Nexo's own FenceRevision. The provider needs independent evidence of its retained ordering state, or Nexo must conservatively treat enforcement as UNKNOWN.

## Critical distinctions
- NEXO_FENCE_HISTORY != PROVIDER_HIGH_WATER_MARK
- SNAPSHOT_RESTORE != ORDERING_CONTINUITY
- HIGHER_RESTORED_VALUE != PROOF_ALL_OLD_TOKENS_ARE_STALE
- PROVIDER_RESTART != PROVIDER_FENCE_RESET
- TOKEN_MONOTONICITY_IN_NEXO != TOKEN_ENFORCEMENT_IN_PROVIDER
- NEW_PROVIDER_EPOCH != OLD_TOKEN_VALIDITY
- HIGH_WATER_MARK_LOSS != SAFE_RECOVERY
- REVISION_BUMP != UNIVERSAL_PROOF unless its bound covers delayed tokens

## Nexo implication
Provider capability evidence for E3-E5 effects must include the persistence/recovery semantics of the provider's fencing high-water mark. If the provider can restore to a lower ordering state without an explicit non-overlapping epoch transition, Nexo must downgrade fencing assurance and prevent protected external admission until reconciliation closes the gap.
