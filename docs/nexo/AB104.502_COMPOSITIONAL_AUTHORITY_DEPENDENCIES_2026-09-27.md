# AB104.502 — compositional authority dependencies, circular assumptions, common-mode failure

## Evidence
Assume-guarantee reasoning explicitly addresses circular component assumptions and provides sound rules for discharging them rather than simply trusting mutually dependent claims. citeturn0search1turn0search8 Contract frameworks also provide compositional rules for interconnected components and distinguish cases with cycles from acyclic compositions. citeturn0search5turn0search15 Common-mode analysis warns that redundant components cannot be treated as independent when they share a failure mechanism or dependency. citeturn0search3

## Nexo dependency contract
Model each certificate dependency as a component contract:
`D_i = (Inputs_i, Assumptions_i, Guarantees_i, FailureOutcomes_i, TrustBasis_i, DependencySet_i)`.

Candidate protected dependency set for an authority certificate:
`{Membership, TrustBasis, Checkpoint, Fence, Evidence, Profile/MigrationState}`.

A global authority decision is admissible only if every required dependency contract is satisfied under a coherent snapshot and no dependency relies on the decision itself in an unsatisfied circular way.

## Circular assumptions
A dangerous pattern is:
`Membership assumes TrustBasis -> TrustBasis assumes Membership`.

Mutual assumptions cannot be accepted merely because both components produce locally valid certificates. The cycle needs either:
1. an independent base invariant/trust anchor that breaks the cycle;
2. a simultaneous fixed-point proof with explicitly defined semantics; or
3. rejection/quarantine because the authority basis is unresolved.

This follows the general assume-guarantee problem: local verification can be circular, but sound circular reasoning requires a rule that establishes the assumptions rather than postulating them. citeturn0search1turn0search8

## Common-mode dependency closure
Two apparently independent witnesses are not independent for authority if both depend on the same compromised membership database, signing root, parser, migration policy, or checkpoint source.

Candidate closure:
`EffectiveIndependence(S) = Independence(S \ CommonDependencyClosure(S))`.

Therefore raw signer count or threshold weight cannot substitute for dependency independence. Common-mode failure analysis explicitly requires independence rather than assuming redundancy is independent. citeturn0search3

## Compositional promotion gate
For claim C:
1. build dependency graph;
2. identify required dependency contracts;
3. compute transitive/common-mode dependency closure;
4. reject unresolved circular assumptions unless an independent rule discharges them;
5. validate every contract against the same authority/profile epoch;
6. compose guarantees only after assumptions are discharged;
7. include dependency failures and quarantine in the global observable outcome.

## New distinction
`LOCAL_CERTIFICATE_VALIDITY != COMPOSED_AUTHORITY_VALIDITY`.

A set of individually valid certificates may still fail composition because their epochs, trust bases, checkpoints, or assumptions conflict.

## Candidate invariant set
- `UNDISCHARGED_CIRCULAR_ASSUMPTION => NO_AUTHORITY`
- `COMMON_DEPENDENCY => NOT_INDEPENDENT`
- `LOCAL_VALIDITY != COMPOSED_VALIDITY`
- `DEPENDENCY_EPOCH_MISMATCH => REJECT_OR_QUARANTINE`
- `TRUST_BASIS_CONFLICT => UNKNOWN_AUTHORITY`
- `COMPOSED_ALLOW REQUIRES ALL REQUIRED ASSUMPTIONS_DISCHARGED`
- `RAW_QUORUM_COUNT != EFFECTIVE_INDEPENDENCE`
- `CERTIFICATE_CHAIN != AUTOMATIC_TRUST_CHAIN`
