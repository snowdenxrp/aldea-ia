# Nexo AB104.451 — Simultaneous Compromise of Primary, Backup/Escrow and Recovery Infrastructure

Date: 2026-09-27
Status: RESEARCH / DESIGN ONLY
Continuity: AB104.450 → AB104.451
Implementation: NOT PERFORMED

## Research question

What can Nexo safely establish when the primary authority, backup/escrow system, and ordinary recovery infrastructure may all be compromised or unavailable?

## External evidence

NIST defines compromise recovery as restoring a compromised system to a secure/trusted state, including destroying/replacing compromised keys and verifying the recovered state. citeturn0search1

NIST SP 800-57 notes that recovery requires redundancy, but increasing the number of copies also increases exposure to compromise. It separately requires revocation/replacement and damage assessment when key compromise occurs. citeturn0search5

RFC 6024 explicitly treats recovery from loss or compromise of a trust-anchor private key, including the key used by a trust-anchor manager, as a required trust-anchor-management capability. It also notes that initial trust-anchor management depends on some pre-established trust basis. citeturn0search2

NIST SP 800-193 similarly treats recovery mechanisms as security-sensitive and emphasizes protected recovery paths rather than assuming the normal platform path can recover itself. citeturn0search0

## Core finding

There is a hard epistemic boundary.

If every available authority/currentness source for claim C is inside the compromised dependency closure, Nexo cannot manufacture an independent current-state fact from those same sources.

Therefore:

NO_INDEPENDENT_TRUST_BASIS
=>
CURRENT_AUTHORITY(C) = UNKNOWN.

This is not a system failure to be patched away. It is a required safety state.

## Attack X1 — primary + backup compromised

Primary authority and every backup are in the same compromise closure.

The newest backup cannot prove that it is current or uncompromised.

Result:
LATEST_BACKUP != CURRENT_TRUST.

## Attack X2 — primary + escrow compromised

Escrow can reconstruct old authority.

It cannot independently establish that the reconstructed authority remains valid.

Result:
ESCROW_RECONSTRUCTION != TRUST_RECONSTRUCTION.

## Attack X3 — recovery verifier compromised

The recovery verifier certifies a fresh device as healthy, but the verifier itself is inside the compromised closure.

Its attestation is not independent for claims relying on verifier integrity.

Result:
COMPROMISED_VERIFIER => INVALID/UNKNOWN_FOR_DEPENDENT_CLAIMS.

## Attack X4 — all witnesses share one hidden dependency

Several external witnesses appear independent but rely on the same identity provider, cloud control plane, software supply chain, operator, or root key.

A quorum can therefore collapse to one failure domain.

Result:
WITNESS_COUNT != INDEPENDENT_EVIDENCE_COUNT.

## Attack X5 — new key generated inside compromised environment

A fresh key pair is generated after compromise, but generation occurs on compromised infrastructure.

Cryptographic novelty does not establish trustworthy provenance.

Result:
NEW_KEY != NEW_TRUST_BASIS.

## Attack X6 — fresh hardware, compromised provisioning

New hardware is genuine, but provisioning credentials/configuration are controlled by the compromised domain.

Hardware authenticity alone cannot establish current authority.

Result:
HARDWARE_AUTHENTICITY != AUTHORITY_RECOVERY.

## Attack X7 — external timestamp treated as authority

An external clock or timestamp says the recovery happened after compromise.

Time can order events but cannot by itself establish which state is authoritative.

Result:
TIME_ORDER != TRUST_AUTHORITY.

## Attack X8 — newest signed state wins

Two states exist:
S49 and S49'.

Both have valid signatures from compromised infrastructure.

Choosing the newest or lexicographically largest state does not restore independent trust.

Result:
SIGNATURE_VALIDITY + MAX_GENERATION != CURRENT_TRUST.

## Attack X9 — human operator as automatic root

An operator claims:
“I inspected the system; it is recovered.”

Human intervention can be a recovery authority only if Nexo explicitly defines and protects that governance path.

An informal assertion is not automatically machine-verifiable authority.

Result:
OPERATOR_ASSERTION != AUTHORITY unless governed.

## Attack X10 — emergency threshold bypass

No quorum remains.
Emergency procedure lowers the threshold to one operator.

This converts loss of trust into automatic authority escalation.

Result:
NO_QUORUM != PERMISSION_TO_LOWER_SAFETY.

## Attack X11 — recovery from pre-compromise checkpoint

An independently validated checkpoint exists at G40.
Current compromised system claims G55.

G40 may be trusted historical state, but it does not prove G55.

Result:
LAST_TRUSTED_CHECKPOINT != CURRENT_STATE.

It can serve as a reconstruction boundary.

## Attack X12 — external effect history survives but authority history does not

Provider logs prove:
EffectID E17 occurred.

That establishes an external observation about E17, not that Nexo was authorized to issue it.

Result:
EXTERNAL_EFFECT_EVIDENCE != AUTHORITY_EVIDENCE.

## Attack X13 — authority survives but effect history is lost

Nexo can reconstruct authority but cannot determine whether an irreversible external effect already occurred.

The correct state is:
AUTHORITY_RECOVERED + EFFECT_STATE_UNKNOWN.

Do not retry an irreversible operation solely because authority has been recovered.

## Attack X14 — conflicting independent recovery authorities

Two genuinely independent recovery authorities produce different recovery generations.

This is not resolved by simple recency.

Candidate:
RECOVERY_CONFLICT
→ FREEZE_HIGH_CONSEQUENCE_TRANSITIONS
→ PRESERVE_BOTH_EVIDENCE_BRANCHES
→ EXTERNAL_GOVERNANCE_RESOLUTION.

## Minimum surviving trust basis

For claim C, safe recovery requires at least one of:

1. An independent surviving authority that can legitimately authorize recovery.
2. An independently validated continuity anchor plus a protected governance path that can establish a new authority.
3. An explicitly defined external recovery authority/governance process.

If none exists:
CURRENT_AUTHORITY(C) = UNKNOWN.

## Important distinction: history vs authority

Even when current authority becomes UNKNOWN, Nexo should preserve evidence that can still be useful:

- last independently validated state;
- immutable local history where integrity remains established;
- external effect observations;
- independent witness observations;
- compromise interval hypotheses;
- affected dependency graph;
- revoked/retired credentials;
- conflicting recovery branches.

Evidence can survive even when authority cannot.

## Terminal UNKNOWN boundary

Candidate state:

TRUST_RECOVERY_BLOCKED

when:

- no independent authority remains;
- all currentness sources are compromised/unavailable;
- recovery governance cannot be independently authenticated;
- conflicting recovery histories cannot be resolved.

Required behavior:

- block high-consequence protected transitions;
- do not mint normal authority;
- do not lower threshold automatically;
- do not declare newest state current;
- preserve evidence;
- allow only explicitly scoped forensic/read-only recovery;
- await external recovery authority.

## Recovery from terminal UNKNOWN

Candidate:

EXTERNAL_RECOVERY_AUTHORITY_PRESENT
→ AUTHENTICATE_EXTERNAL_AUTHORITY
→ VERIFY_SCOPE
→ VERIFY_RECOVERY_POLICY
→ ESTABLISH_NEW_TRUST_ROOTS
→ CREATE_NEW_INCARNATIONS
→ INVALIDATE_COMPROMISED_ROOTS
→ RECONSTRUCT_HISTORY
→ RECONCILE_EFFECTS
→ COMMIT_NEW_RECOVERY_GENERATION
→ EXPLICIT_RELEASE.

The external authority is not assumed to be trustworthy merely because it is external; its own dependency closure and governance basis must be evaluated.

## No circular recovery

Forbidden cycle:

NEW_ROOT
→ validates RECOVERY_AUTHORITY
→ RECOVERY_AUTHORITY validates NEW_ROOT.

This is circular.

Candidate recovery graph must have an acyclic trusted basis, or an independently established root of governance.

## Recovery graph model

Each trust claim should maintain:

CLAIM
→ REQUIRED_TRUST_BASIS
→ DEPENDENCY_CLOSURE
→ CURRENTNESS_SOURCE
→ RECOVERY_AUTHORITY
→ INVALIDATION_PATH.

If recovery authority is contained in the claim's compromised closure, that recovery path is invalid for the claim.

## External authority does not erase uncertainty

Even after an external recovery authority establishes G60:

- pre-G60 claims remain separately classified;
- disputed history remains disputed;
- unknown effects remain unknown;
- compromised credentials remain invalid;
- new authority begins at an explicit recovery generation.

Therefore:

NEW_RECOVERY_AUTHORITY != HISTORICAL_CORRECTION.

## Important result for Nexo

This closes an important conceptual boundary:

Nexo does not need to “always recover.”

It needs to recover safely when an independently grounded recovery basis exists, and otherwise **stop making claims it cannot justify**.

That is a safety property, not a missing feature.
