# AB104.483 — independent witnesses and split-view detection

RFC 9162 identifies split-view behavior as a weakness of a transparency log: different clients can receive inconsistent tree views. It describes gossip as a mechanism in which clients compare signed tree heads (STHs); conflicting STHs can provide cryptographic evidence of log misbehavior. The RFC also notes that gossip itself is an active research area rather than a complete protocol in RFC 9162. citeturn0search0

## Witness model

For Nexo, an independent witness can retain a checkpoint:
`LOG_ID + TREE_SIZE + ROOT_HASH + SIGNATURE + OBSERVED_AT`

A later checkpoint can be accepted only when consistency with the retained checkpoint is proven. Two incompatible signed checkpoints for the same log identity and incompatible tree history are an equivocation signal.

## Independence boundary

Witness count is not witness independence. If all witnesses share the same operator, signing key, storage, network control plane, or compromised upstream trust root, multiple observations may represent one failure domain. Therefore:
`WITNESS_COUNT != INDEPENDENCE`
`REPLICA_COUNT != INDEPENDENCE`
`GOSSIP_PARTICIPANTS != INDEPENDENT_TRUST_BASES`

## Checkpoint anchoring

A durable Nexo checkpoint can improve recovery against rollback or forked transparency history, but the checkpoint itself needs a trust basis and lifecycle. A new checkpoint cannot silently replace an older conflicting checkpoint. Conflict requires quarantine and reconciliation.

## Claim boundary

Independent witnesses strengthen evidence that a particular log history existed and was not presented consistently. They do not prove the underlying claim was true, that the external resource currently exists, or that the effect was authorized.

New invariants:
- SPLIT_VIEW_DETECTED => AFFECTED_LOG_HISTORY_QUARANTINED
- CONFLICTING_SIGNED_CHECKPOINTS != CURRENT_EXTERNAL_STATE
- WITNESS_COUNT != INDEPENDENCE
- REPLICA_COUNT != INDEPENDENCE
- GOSSIP_DETECTION != AUTOMATIC_AUTHORIZATION
- CHECKPOINT_REPLACEMENT_REQUIRES_EXPLICIT_TRUST_TRANSITION
- SAME_FAILURE_DOMAIN => NO_INDEPENDENCE_CLAIM
- TRANSPARENCY_WITNESS_EVIDENCE != PROVIDER_EFFECT_CONFIRMATION

Evidence status: independent witnesses and cross-checking materially strengthen split-view/equivocation detection, but witness independence must be demonstrated per failure domain and does not turn transparency history into external-state authority.
