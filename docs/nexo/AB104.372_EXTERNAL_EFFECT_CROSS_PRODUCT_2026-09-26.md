# Nexo AB104.372 — Adversarial Cross-Product: External Effect Admission
Date: 2026-09-26
Status: RESEARCH / DESIGN EVIDENCE ONLY

No implementation. No formal proof. No runtime verification.

## Objective
Test combinations of authority freshness, target freshness, effect identity, provider fencing, conditional state checks, idempotency, durable intent, acknowledgement, and reconciliation.

## Evidence anchors
- RFC 9110 If-Match: recipient evaluates the precondition before performing the method; a false condition must not apply the requested method, subject to the documented already-applied 2xx case. https://www.rfc-editor.org/rfc/rfc9110.html
- AWS guidance: deterministic idempotency keys and conditional writes can make retries safer, but retry semantics depend on the operation/provider. AWS Durable Execution explicitly distinguishes at-least-once and at-most-once semantics. 
- Idempotency does not itself establish authority freshness or remote cancellation.

## Cross-product classification
SAFE-ADMISSIBLE* = candidate admission under the proposed contract, NOT a proof of safety.

1. Fresh authority + fresh target + unique stable EffectID + provider fence + provider conditional state + durable intent + acknowledgement + reconciliation: SAFE-ADMISSIBLE*.
2. Fresh authority + stale target: REJECTED.
3. Stale authority + fresh target, regardless of idempotency: REJECTED.
4. Authority freshness UNKNOWN: HOLD/REVALIDATE.
5. Target freshness UNKNOWN: HOLD/REVALIDATE.
6. Stable EffectID absent with retryable side effect: HOLD/REJECTED unless effect class is independently idempotent.
7. Provider fence absent but authority must remain current through external attempt: HOLD/REVALIDATE; cannot claim stale-authority exclusion from local state alone.
8. Provider conditional state absent with a required target precondition: HOLD/REVALIDATE or REJECTED.
9. Durable intent absent before a crash-sensitive external attempt: HOLD/REJECTED when durable intent is required by the effect class.
10. Provider acknowledgement absent after attempt: UNKNOWN unless independent evidence establishes outcome.
11. Reconciliation unavailable after ambiguous attempt: UNKNOWN; do not infer non-execution from missing acknowledgement.
12. Idempotency present but authority fence absent: retry-duplication risk is reduced, but stale-authority risk remains; HOLD/REVALIDATE for protected effects.
13. Conditional target check present but authority fence absent: stale target can be rejected, but stale authority remains unresolved; HOLD/REVALIDATE.
14. Provider fence present but EffectID unstable across retries: stale-generation protection may exist, but duplicate logical effects remain possible; HOLD/REVALIDATE unless provider semantics prove equivalence.
15. Durable intent + stable EffectID but no provider fence: durable recovery/retry identity exists, but current authorization at provider is unresolved; HOLD/REVALIDATE.
16. Local control linearization succeeded, then authority revoked before external attempt: local transition remains historical; external effect requires fresh/fenced authorization; otherwise HOLD/REVALIDATE.
17. External attempt occurred and response is lost: UNKNOWN unless reconciliation or provider query proves outcome.
18. Reconciliation proves exact effect identity and provider state: EXTERNAL_CONFIRMED or REJECTED according to observed state; evidence must be bound to the claim.
19. Provider says request rejected by stale fence: REJECTED for that attempt; do not treat as external success.
20. Provider reports success for a valid fenced EffectID: candidate EXTERNAL_CONFIRMED, subject to evidence/identity/reconciliation contract.

## Adversarial invariant matrix
- NO_EFFECT_FROM_STALE_AUTHORITY requires provider-side enforcement or an equivalent trusted atomic frontier; client-side observation alone is insufficient.
- NO_ACCEPTED_EXTERNAL_EFFECT_FROM_STALE_FENCE requires the provider to enforce the fence.
- NO_INFERENCE_FROM_MISSING_ACK: missing response does not establish non-execution.
- RETRY_IS_NOT_EFFECT_IDENTITY: each retry is not a new logical effect when stable identity is required.
- REVOCATION_IS_NOT_RETROACTIVE: revocation after a committed local transition does not erase that historical transition; external execution needs its own gate.
- CONTROL_LINEARIZATION != EXTERNAL_ATTEMPT != EXTERNAL_CONFIRMATION.

## Important residuals
- Effect classes still need explicit atomicity/authorization requirements.
- Provider capabilities must be modeled per resource/effect class, not assumed globally.
- Need a precise rule for when provider fence + conditional state + EffectID are jointly sufficient.
- Need treatment of non-idempotent irreversible effects.
- Need reconciliation evidence independence/common-mode analysis.
- Need multi-provider and cross-resource composition analysis.
- No technology selection.
