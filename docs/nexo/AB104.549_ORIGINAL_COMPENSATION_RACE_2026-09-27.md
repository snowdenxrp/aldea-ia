# Nexo AB104.549 — Original effect versus compensation race

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
A compensating action must not be treated as a cancellation barrier for an earlier UNKNOWN effect. The original effect and its compensation are independent effect lifecycles. Delayed original messages can arrive after compensation, and retries of the original can race with the compensator. Therefore compensation requires an explicit dependency/ordering rule and stale-effect rejection where the target supports it.

## Evidence
AWS Saga guidance states that saga participants need idempotency because retries can occur, and that saga lacks transaction isolation; concurrent orchestration can observe stale data and may require semantic locking. AWS also distinguishes forward recovery from backward compensation. These properties directly expose the race between delayed original operations and compensating operations. citeturn0search0turn0search1turn0search4

## Race
O = original effect
C = compensation

Possible timeline:
O dispatched -> outcome UNKNOWN -> C admitted -> C applied -> delayed O arrives

If the target accepts O after C, the final state can regress. Therefore C completion alone is not proof that O is permanently prevented.

## Candidate dependency model
C carries:
- OriginalEffectID
- OriginalAttemptSet/Digest
- CompensationEffectID
- RequiredOriginalTerminalState
- AuthorityEpoch/FenceRevision
- TargetIncarnation
- CompensationPolicy

Before C is admitted, the system should establish the strongest available predicate that O cannot newly take effect, such as provider-side cancellation/version condition/fencing. If no such predicate exists, C must be classified as compensation-under-uncertainty rather than as a proof that O is gone.

## Safe patterns
1. Provider conditional mutation: O and C both require the current target version/fence; C advances the version so stale O is rejected.
2. Tombstone/cancellation record: target records the EffectID as cancelled before accepting future O attempts.
3. Durable serialized executor: O and C are ordered by one authoritative execution log.
4. Reconciliation-first: C waits until O's outcome is resolved.
5. Semantic compensation: C produces an acceptable new state even if O eventually arrived, but only when business semantics explicitly permit that outcome.

## Unsafe assumption
`COMPENSATION_CONFIRMED -> ORIGINAL_NOT_EXECUTABLE`
is false unless the target enforces a causal barrier against O.

Likewise:
`NEWER_FENCE_FOR_C -> OLD_O_CANNOT_ARRIVE`
is false. A fence can reject old authority only if the target actually enforces it.

## Compensation lifecycle
C itself can become UNKNOWN:
C_DISPATCHED -> ACK_LOST -> C_UNKNOWN
Therefore C requires its own EffectID, idempotency/reconciliation, fence semantics, and terminal recovery policy.

## Delayed-message boundary
A delayed O may be harmless if the target checks an authoritative cancellation/tombstone/version. Without such a check, the system must preserve UNKNOWN and avoid declaring the saga reconciled.

## Critical distinctions
- COMPENSATION_CONFIRMED != ORIGINAL_NOT_EXECUTABLE
- COMPENSATION != CANCELLATION
- NEWER_FENCE != RETROACTIVE_MESSAGE_REMOVAL
- C_APPLIED != O_NEVER_APPLIED
- O_UNKNOWN != O_FAILED
- C_UNKNOWN != C_FAILED
- RECONCILIATION != ROLLBACK
- SERIALIZATION != CROSS_DOMAIN_ATOMICITY
- SEMANTIC_COMPENSATION != EXACT_INVERSE

## Nexo implication
The effect contract should model explicit causal dependencies between original and compensating effects. When possible, the target must enforce a cancellation/version/fence barrier before compensation is admitted. Otherwise the result remains a controlled UNKNOWN and cannot be promoted to a terminal success merely because compensation completed.
