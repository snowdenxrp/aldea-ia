# NEXO AB104.750R — MockSelector → NetworkClient.poll() exception-surface re-audit

Date: 2026-09-28
Source baseline: Apache Kafka abf522e1ca5d7f4375baddc4da004da9fcb6e9ca

## Direct source findings

`MockSelector.completeReceive(NetworkReceive)` does not serialize, validate, or transform the receive; it appends it directly to `completedReceives`.

`MockSelector.poll()` completes initiated sends, moves delayed receives whose source matches a completed send into `completedReceives`, then advances test time. `completedReceives()` returns the backing list.

`NetworkClient.poll()` subsequently reaches `handleCompletedReceives()`, where the receive source is used to remove the next in-flight request before `NetworkClient.parseResponse()` validates the correlation ID.

Therefore the exact adversarial recipe is mechanically available: construct a response with an independently chosen correlation ID, inject it with `completeReceive`, then call `NetworkClient.poll()`. However, repository inspection still did not find a test that actually performs that mismatch through this complete path and asserts the exception.

## Existing test boundary

`NetworkClientTest.checkSimpleRequestResponse()` executes the completeReceive → poll path, but uses `request.correlationId()` and therefore is a matching case. Other `NetworkClientTest` uses of `completeReceive` similarly do not establish a dedicated mismatch assertion.

A repository search for the NetworkClient mismatch exception surface did not produce a dedicated test.
