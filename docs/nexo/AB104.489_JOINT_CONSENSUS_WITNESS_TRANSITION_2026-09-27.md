# AB104.489 — joint-consensus witness membership/threshold transition

## Evidence
Raft's joint-consensus design transitions through a configuration containing both old and new memberships; agreement requires a majority of both configurations during the joint phase, preventing independent old/new majorities from committing conflicting decisions. citeturn0search36turn0search0

The current etcd/raft implementation provides concrete source-level evidence: non-simple membership changes use Joint Consensus, with quorum requiring majorities of both pre-change and post-change configurations; it also prevents concurrent uncommitted membership changes. citeturn0search1turn0search5

## Nexo adaptation
For witness-set replacement or threshold change, the protected transition should be:

`E_old → E_joint(old,new) → E_new`

During `E_joint`, authorization requires the explicitly defined intersection condition across old and new configurations. `E_new` cannot become sole authority until the joint transition is durably committed.

Candidate transition record:
`OldEpoch + NewEpoch + OldMembers + NewMembers + OldThreshold + NewThreshold + ParentCheckpoint + TrustBasisTransition + PolicyVersion + TransitionRevision`

The record must be durable and uniquely ordered by the authoritative state machine. Concurrent configuration transitions must be rejected or serialized; otherwise different quorum requirements can create a dual-authority window. etcd's implementation explicitly disallows a second membership change while an uncommitted change exists. citeturn0search1

## Important Nexo-specific limitation
Ordinary Raft joint consensus assumes the old configuration is still a trustworthy participant set. Nexo's use case may involve a **compromised** old witness set. Therefore, blindly requiring old-member approval can make recovery impossible or allow compromised witnesses to retain too much authority.

This creates a separate research branch:
`JOINT_CONSENSUS_FOR_CRASH_FAILURES != JOINT_RECOVERY_AFTER_TRUST_COMPROMISE`

A compromise-aware transition needs an independent recovery authority/trust basis and an explicit rule defining which old witnesses, if any, remain admissible only as historical evidence rather than voting authority.

## Threshold transition
Changing threshold is itself an authority transition. A lower threshold must never be introduced merely because the old quorum is unavailable. If the new threshold differs, the transition record must bind old/new thresholds and the trust basis that authorizes the change.

## Status
Research complete. Joint Consensus supplies a strong concrete pattern for safe configuration transition, but it does not by itself solve Nexo's stronger trust-compromise case. No implementation or formal verification performed.
