## Verified at pinned Kafka revision
Kafka revision: 99b940733a9f6bc409457dba7108f08421d81e42.

KafkaClusterTestKit at this revision natively configures SASL/PLAIN for SASL_PLAINTEXT brokers, installs StandardAuthorizer, and defines the superuser User:plain-admin. Its JAAS test identities are plain-user1 / plain-user1-secret and plain-admin / plain-admin-secret.

The TestKit node builder validates per-server property IDs and uses broker ID 0 for the first non-combined broker; controller-only nodes use the controller offset.

## Runtime consequence
The runtime harness can use the native TestKit SASL/PLAIN setup rather than inventing a separate authentication bootstrap. The admin identity can remain the TestKit superuser while the producer uses plain-user1.

For the producer path, Kafka authorization documentation identifies normal PRODUCE as WRITE on the Topic resource, while METADATA requires DESCRIBE and DELETE_ACLS requires ALTER on Cluster. Therefore the runtime test must distinguish auxiliary DESCRIBE access from the target WRITE ACL: D0 removes only the target WRITE permission, and D1 must demonstrate denial of the Produce WRITE operation rather than merely failing metadata discovery.

## Evidence boundary
Source inspection establishes the executable design, not the race result. Only an actual recoverable run containing A1 -> D0 -> D1 -> release -> D2 -> E can change EXACT_RACE from UNKNOWN.
