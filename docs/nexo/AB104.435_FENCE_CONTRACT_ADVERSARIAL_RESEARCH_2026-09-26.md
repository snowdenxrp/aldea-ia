# Nexo AB104.435 — Adversarial Fence Contract Research

Date: 2026-09-26
Status: RESEARCH / DESIGN ONLY
Continuity: AB104.434 → AB104.435
Implementation: NOT PERFORMED

## Objective

Attack the provider-independent Fence Contract against real distributed-system failure patterns before accepting it as an architectural requirement.

## Adversarial cases

### A1 — delayed old request

G7 is superseded by G8. A delayed G7 request arrives after G8 is active.

Required property:
RESOURCE MUST REJECT G7.

Fence contract survives if enforcement occurs at the resource boundary and generation/incarnation are checked there.

### A2 — duplicate request after restart

Operation O7 is submitted, process crashes, then the same request arrives again.

Required property:
DUPLICATE_O7 MUST NOT BECOME A NEW EFFECT IDENTITY.

Fence alone is insufficient; durable operation/replay identity remains required.

### A3 — generation rollback

Storage restores an older snapshot containing G7 after G8 was authoritative.

Required property:
G7 MUST NOT silently become current.

Fence contract therefore depends on continuity protection outside the local process.

### A4 — same generation, different authority incarnation

Authority A and replacement authority B both emit G8.

Required property:
GENERATION_EQUALITY MUST NOT IMPLY AUTHORITY_EQUALITY.

Incarnation/authority identity must participate in the protected binding.

### A5 — lease expires, old holder continues

Old holder's lease expires; new holder obtains authority; old holder sends a delayed mutation.

Required property:
OLD HOLDER MUST BE REJECTED.

Lease semantics alone are insufficient unless the resource enforces fencing.

### A6 — split brain

Two authorities believe they are current.

Required property:
RESOURCE MUST NOT ACCEPT CONFLICTING AUTHORITY WITHOUT AN EXPLICIT EXCLUSION MECHANISM.

The Fence Contract cannot solve a broken authority-election system by itself; it must receive an authoritative generation/incarnation.

### A7 — watch gap

Consumer receives G8 and G10 but misses G9.

Required property:
CONSUMER MUST NOT ASSUME G9 WAS BENIGN.

Gap detection must force snapshot/revalidation.

### A8 — stale snapshot

A cryptographically valid snapshot containing G7 is restored after G8.

Required property:
VALID_SIGNATURE != CURRENT_AUTHORITY.

Continuity/currentness validation remains mandatory.

### A9 — resource restart resets fence

Resource restarts and initializes fence to default G0.

Required property:
OLD_REQUESTS MUST NOT BECOME ACCEPTABLE BECAUSE OF RESET.

Safe recovery requires preserved/advanced fence state or quarantine.

### A10 — external effect ambiguity

Fence succeeds and external provider request is sent, but process crashes before result recording.

Required property:
FENCE_SUCCESS != EXTERNAL_EFFECT_CONFIRMED.

Effect reconciliation remains a separate proof obligation.

## Provider-transferability result

The research supports the abstraction but rejects several overly strong interpretations.

### Transferable properties

- stale-generation rejection at the protected resource boundary;
- generation/incarnation binding;
- durable replay/effect identity;
- explicit recovery continuity;
- gap detection and revalidation;
- separation of authority from external-effect confirmation.

### Non-transferable assumptions

- lease expiry alone guarantees stale-request rejection;
- a strong read automatically protects a later external effect;
- a generation number alone uniquely identifies authority;
- a signed snapshot is necessarily current;
- a quorum automatically provides independent truth;
- local process restart automatically establishes safe authority.

## Refined Fence Contract

For a protected resource mutation:

ACCEPT iff:

1. request authority domain is correct;
2. request authority incarnation matches current protected authority incarnation;
3. request fence generation matches current resource fence generation;
4. resource incarnation is current;
5. operation/effect identity passes replay policy;
6. required policy/trust generation conditions pass;
7. resource is not quarantined;
8. all required currentness dependencies are satisfied.

Otherwise:

REJECT / HOLD / RECONCILE according to effect class.

## Critical limitation

The Fence Contract is a stale-actor exclusion contract, not a universal authorization contract.

It does not itself prove:

- user intent;
- policy correctness;
- issuer authenticity;
- external effect completion;
- global system consistency;
- absence of common-mode failure;
- correctness of the authority election mechanism.

Those remain separate contracts/evidence dependencies.
