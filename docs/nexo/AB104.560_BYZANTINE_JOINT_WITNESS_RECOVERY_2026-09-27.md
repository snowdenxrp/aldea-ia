# Nexo AB104.560 — Byzantine joint witness recovery

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Evidence
Raft joint consensus is not Byzantine fault tolerant: its safety relies on non-Byzantine participants. A Byzantine witness model therefore needs stronger evidence than ordinary quorum signatures. Byzantine consensus uses signed quorum evidence with safety depending on quorum intersection and bounded Byzantine participants. RFC 9162 provides a useful evidence pattern: consistency proofs demonstrate that two signed tree heads represent a consistent append-only history; a failed audit can yield signed evidence of log misbehavior.

## Finding
During witness-set transition, a valid signature is only evidence that a witness signed bytes. It does not by itself prove authorization in the relevant epoch, absence of equivocation, sufficient independent quorum intersection, valid predecessor binding, or actual commitment.

## Candidate certificate
TransitionCertificate = { transition_id, predecessor_anchor_digest, successor_anchor_digest, old_witness_epoch, new_witness_epoch, phase, membership_digest, authority_epoch, continuity_counter, signer_set, quorum_evidence, predecessor_consistency_proof, dependency_snapshot_digest }

## Equivocation rule
If a witness signs incompatible successor/phase statements for the same transition and epoch, record EQUIVOCATION evidence and invalidate that witness for the affected transition. Do not infer which statement is correct from timestamps or signature count alone.

If conflicting certificates exist, compare authorization epoch, predecessor binding, quorum intersection and independence. If no unique safe ordering is established, enter QUARANTINED.

## Minimum promotion evidence
1. Valid signatures under the correct witness-set epoch.
2. Required quorum/intersection under the threat model.
3. Cryptographic predecessor binding.
4. Phase monotonicity.
5. No unresolved conflicting certificate with equal-or-higher authority.
6. Dependency snapshot still valid.
7. Recovery/continuity anchor compatibility.

A cryptographically valid certificate that fails a semantic condition is not a valid authority certificate.

## Byzantine consequence
A witness quorum can be cryptographically valid while semantically unsafe if concentrated in one compromised failure domain or if membership changed. Therefore VALID_QC != VALID_AUTHORITY.

## Quarantine triggers
- conflicting successor anchors;
- same witness signing incompatible phases;
- certificate from obsolete witness epoch;
- predecessor digest mismatch;
- quorum evidence insufficient after dependency closure;
- missing independent witness coverage;
- unknown commitment state;
- rollback detected in continuity counter.

## Nexo consequence
The witness subsystem needs two separate outputs: EVIDENCE_VALIDATION and AUTHORITY_ADMISSION. The first reports what was signed and whether proofs verify. The second decides whether evidence is sufficient for protected authority. Never collapse them.

Critical distinctions:
VALID_SIGNATURE != VALID_TRANSITION
VALID_QC != VALID_AUTHORITY
QUORUM_COUNT != INDEPENDENCE
EQUIVOCATION_PROOF != CORRECT_SUCCESSOR
CONSISTENCY_PROOF != EXECUTION_AUTHORITY
CRYPTOGRAPHIC_VALIDITY != SEMANTIC_VALIDITY
