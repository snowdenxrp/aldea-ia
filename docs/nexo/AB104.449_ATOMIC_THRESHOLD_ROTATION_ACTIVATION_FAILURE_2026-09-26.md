# Nexo AB104.449 — Atomic Activation and Partial-Failure Attack for Threshold Rotation

Date: 2026-09-26
Status: RESEARCH / DESIGN ONLY
Continuity: AB104.448 → AB104.449
Implementation: NOT PERFORMED

## Research question

How should Nexo handle crashes, partial distribution, split activation, backup restoration, and old/new share overlap during threshold membership rotation?

## Evidence

NISTIR 8214 explicitly identifies rejuvenation/replacement as a separate protocol concern, including stateful-node consistency, parallel/sequential recovery, dealer dependencies, and the possibility that recovery has different synchrony assumptions from normal operation. citeturn0search36

NIST's current threshold work continues to treat recovery mechanisms against mobile/adaptive compromise as an additional consideration rather than an automatic property of the threshold primitive. citeturn0search38turn0search0

Dynamic proactive secret-sharing research demonstrates that participant-set changes are a distinct protocol problem, not merely a metadata update. citeturn0search6

Proactive threshold-signature research shows that share refresh can preserve a public key and threshold in some constructions, confirming that cryptographic continuity and governance-state continuity are separate dimensions. citeturn0search4

## Core finding

A rotation is unsafe if individual participants can independently conclude that the new generation is active.

Therefore:

LOCAL_ROTATION_SUCCESS != GLOBAL_ACTIVATION.

The protected activation boundary must be a single authoritative state transition.

## Attack A1 — split activation

Nodes A/B activate generation G+1.
Nodes C/D remain on G.

Both sides accept signatures according to different membership state.

Result:
SPLIT_GOVERNANCE_STATE.

Candidate response:
freeze affected protected transitions until one authoritative generation is established.

## Attack A2 — crash before activation

All new shares are distributed, but the authoritative activation record is not committed.

The new shares exist, but G+1 is not current.

Therefore:
DISTRIBUTION_COMPLETE != ACTIVATED.

Recovery must reconstruct from durable authoritative state, not infer activation from participant-local state.

## Attack A3 — activation committed, node misses notification

Z1 commits G+1.
Node D remains locally on G because it missed the update.

D must not be able to authorize G operations merely because its local state says G.

Current authority must be obtained from authoritative current state or a bounded valid lease/fence.

## Attack A4 — activation committed, then storage rollback

Authoritative store is restored to a pre-activation snapshot.

Old generation appears current.

Therefore:
SNAPSHOT_RESTORE != CURRENT_AUTHORITY.

Anti-rollback continuity must fence G after G+1 becomes durable.

## Attack A5 — old and new shares overlap

Before cutover, both G and G+1 partial signatures may exist.

They must not both be accepted as current authority.

Candidate:
ACTIVE_GENERATION = exactly one protected generation per authority domain.

If a transition intentionally permits overlap, the overlap must have an explicit bounded semantic, not implicit dual validity.

## Attack A6 — backup contains old share

A backup of a removed member is restored.

The cryptographic material may still be valid.

Therefore backup restoration is a security transition.

Candidate:
RESTORED_CREDENTIALS require current incarnation + generation authorization before use.

## Attack A7 — partial membership activation

New set S+ has only some members operational.

Do not infer:
“enough new members exist, therefore S+ is current.”

Membership activation and availability are separate.

## Attack A8 — threshold changed simultaneously

Old policy: 3-of-5.
New policy: 4-of-7.

If member activation and threshold update occur independently, intermediate states can become ambiguous.

Candidate:
if logical authority requires them together, bind both to one governance transition ID and generation.

## Attack A9 — crash between revocation and activation

Old members are revoked first.
New set is not yet active.

This may create a safe but unavailable state.

Do not restore old members automatically merely to regain availability unless a separately authorized rollback transition exists.

## Attack A10 — crash between activation and old-member fencing

If activation and fencing are separate, old members may remain accepted after new state is current.

Therefore fencing must be part of the protected activation semantics or have an equivalent atomic/linearizable boundary.

## Attack A11 — observer sees impossible sequence

Audit shows:
G+1 ACTIVE
then later
G ACTIVE.

This is not an ordinary rollback.

Candidate:
GENERATION_DECREASE => CONTINUITY_VIOLATION / QUARANTINE.

## Attack A12 — two recovery processes activate different generations

Recovery process R1 activates G+1.
Recovery process R2 activates G+2 from a stale basis.

Both may have valid cryptographic evidence.

Need recovery ownership/fencing:
one recovery authority per protected domain/generation.

## Atomic activation boundary

At the authoritative linearization point:

1. verify CURRENT_GENERATION;
2. verify TARGET_GENERATION;
3. verify target policy/member set;
4. verify required participant evidence;
5. verify no conflicting recovery owner;
6. advance authoritative generation;
7. install target member/threshold state;
8. establish old-generation fence;
9. durably record activation evidence.

If all cannot be established under the protected transition, activation does not occur.

## Recovery reconstruction

After crash, reconstruct from:

- durable authoritative rotation record;
- current governance generation;
- activation status;
- member-set digest;
- policy generation;
- recovery generation;
- participant evidence;
- fencing state.

Never infer current authority solely from:
- local share existence;
- successful network messages;
- backup contents;
- cryptographic signatures from old generation;
- participant-local “activated” flags.

## Unknown activation

If durable state cannot determine whether activation crossed the protected boundary:

UNKNOWN_ACTIVATION.

Do not choose:
“probably old”
or
“probably new.”

For high-consequence authority, UNKNOWN => HOLD/QUARANTINE until independent reconstruction resolves the boundary.

## Backup rule

A backup is historical material, not current authority.

RESTORED_BACKUP
→ AUTHENTICATE
→ INCARNATION_CHECK
→ GENERATION_CHECK
→ POLICY_CHECK
→ DEPENDENCY_CHECK
→ EXPLICIT_REACTIVATION
or
QUARANTINE.

## Rollback rule

Ordinary rollback may not decrease authority generation.

Candidate:
CURRENT_GENERATION_MUST_BE_MONOTONIC_OR_EQUIVALENTLY_FENCED.

If a physical snapshot is older, it can only be used as historical input to recovery, not silently promoted to current state.

## Availability vs safety

A partial rotation can produce:
- safe/unavailable;
- unsafe/available;
- safe/available;
- unsafe/unavailable.

Nexo must not convert an UNKNOWN or unsafe state into “available” by lowering governance requirements.

## New invariants

- LOCAL_ROTATION_SUCCESS != GLOBAL_ACTIVATION
- DISTRIBUTION_COMPLETE != ACTIVATED
- ACTIVE_GENERATION = ONE_PROTECTED_GENERATION_PER_AUTHORITY_DOMAIN
- SNAPSHOT_RESTORE != CURRENT_AUTHORITY
- RESTORED_CREDENTIALS_REQUIRE_CURRENT_AUTHORIZATION
- MEMBER_ACTIVATION != MEMBER_AVAILABILITY
- COUPLED_POLICY_AND_MEMBERSHIP_CHANGE_REQUIRES_SINGLE_PROTECTED_TRANSITION
- OLD_GENERATION_MUST_BE_FENCED_AT_OR_BEFORE_NEW_AUTHORITY_ACCEPTANCE
- GENERATION_DECREASE => CONTINUITY_VIOLATION
- ONE_RECOVERY_OWNER_PER_PROTECTED_DOMAIN
- PARTIAL != ACTIVATED
- UNKNOWN_ACTIVATION => HIGH_CONSEQUENCE_HOLD/QUARANTINE
- BACKUP != CURRENT_AUTHORITY
- PHYSICAL_ROLLBACK != AUTHORITY_ROLLBACK
- CRYPTOGRAPHIC_VALIDITY_OF_OLD_SHARE != CURRENT_AUTHORITY
- SAFETY_REQUIREMENTS_CANNOT_BE_LOWERED_TO_RESTORE_LIVENESS
