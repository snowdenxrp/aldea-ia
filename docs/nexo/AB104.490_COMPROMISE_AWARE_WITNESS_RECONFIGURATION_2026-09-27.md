# AB104.490 — compromise-aware witness reconfiguration

## Research result
Raft joint consensus prevents conflicting old/new majorities by requiring majorities of both configurations during the transition. citeturn0search37turn0search0 However, that safety argument assumes the old configuration remains a valid voting authority. A trust-domain compromise changes the problem: requiring compromised members to authorize recovery can preserve the very authority being revoked.

## Nexo distinction
`CRASH_RECONFIGURATION != TRUST_COMPROMISE_RECONFIGURATION`

For crash/liveness failures, old+new joint quorum is a strong baseline. For compromise recovery, Nexo needs a protected recovery authority that can explicitly fence the compromised epoch and admit a new epoch without treating compromised signatures as fresh authority.

Candidate flow:
`OLD_ACTIVE -> COMPROMISE_CONFIRMED -> OLD_FENCED -> RECOVERY_AUTHORITY_VALIDATED -> NEW_SET_VALIDATED -> CHECKPOINT_CONTINUITY_VERIFIED -> NEW_EPOCH_COMMITTED -> NEW_ACTIVE`

The old set may remain usable as historical evidence, but once fenced it cannot satisfy the protected authorization predicate for new recovery decisions.

## Quorum transition
A safe compromise-aware transition must prevent two classes of authority from becoming active simultaneously:
1. old compromised quorum;
2. new recovery quorum.

Therefore the transition record must include an explicit fencing epoch/revision and a monotonic authority epoch. Any authorization carrying an epoch below the current fenced boundary is rejected even if its cryptographic signature remains valid.

The new quorum threshold must be justified by the recovery trust basis. Loss of old members cannot itself justify lowering the threshold.

## Independence requirement
Adding new witnesses is insufficient if they inherit the same compromised dependency. The recovery trust basis must account for common operator, key authority, identity provider, deployment control, storage, network/control-plane, and governance dependencies.

## Key invariants
- `COMPROMISED_SIGNATURE != RECOVERY_AUTHORITY`
- `OLD_FENCED_EPOCH => NO_NEW_AUTHORIZATION`
- `KEY_VALIDITY != CURRENT_AUTHORITY`
- `NEW_SET_COUNT != INDEPENDENT_TRUST`
- `OLD_QUORUM_LOSS != THRESHOLD_REDUCTION`
- `RECOVERY_AUTHORITY_MUST_BE_OUTSIDE_COMPROMISED_TRUST_BASIS`
- `HISTORICAL_EVIDENCE != CURRENT_VOTING_POWER`
- `AUTHORITY_EPOCH_MUST_BE_MONOTONIC`
- `ROLLBACK_BELOW_FENCE => REJECT_OR_QUARANTINE`

## Boundary / UNKNOWN
This research does not prove a universal Byzantine reconfiguration protocol. The exact recovery authority, threshold mathematics, and failure-domain model remain open. In particular, if every candidate recovery root shares the compromised trust basis, the safe result may be `UNKNOWN_AUTHORITY` rather than automatic recovery.

No implementation or formal verification performed.
