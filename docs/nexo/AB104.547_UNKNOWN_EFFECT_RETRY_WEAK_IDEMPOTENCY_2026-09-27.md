# Nexo AB104.547 — Retrying UNKNOWN EffectID under newer authority with weak/no provider idempotency

Date: 2026-09-27
Status: RESEARCH COMPLETE — DESIGN INPUT ONLY

## Finding
A newer fence does not by itself make it safe to re-execute an EffectID whose previous attempt is UNKNOWN. If the external provider has no durable idempotency or queryable operation record, Nexo cannot prove that the old attempt did not already take effect. Re-execution can therefore create a duplicate effect. The safe default is HOLD/RECONCILE, not automatic retry.

## Evidence
Stripe describes the classic ambiguous failure: a request can succeed while the response is lost, leaving the client unable to know whether retry is safe; idempotency keys let the server correlate the retry and return the original result. AWS Durable Execution likewise states that at-least-once replay is safe only for idempotent operations and recommends stable idempotency keys for external services; for non-idempotent side effects it recommends at-most-once semantics and reconciliation after interruption. citeturn0search2turn0search0turn0search8

## Decision matrix
Let E = EffectID, F_old = prior fence, F_new = current valid fence.

1. Prior outcome CONFIRMED + same E -> return/reconcile stored result; no new external execution.
2. Prior outcome REJECTED_BEFORE_DISPATCH -> same E may be retried under F_new if contract permits.
3. Prior outcome UNKNOWN + provider supports strong idempotency/query -> reconcile by E, then converge to CONFIRMED/NOT_APPLIED/UNKNOWN.
4. Prior outcome UNKNOWN + provider has no idempotency but has authoritative query by business identity -> query the postcondition before deciding whether another attempt is safe.
5. Prior outcome UNKNOWN + provider has neither idempotency nor reliable query -> automatic retry is NOT proven safe; enter HOLD/RECONCILIATION or require an explicitly weaker-risk policy.
6. Prior outcome UNKNOWN + effect is irreversible/non-compensatable -> never silently retry solely because F_new is newer.

## Why newer fencing is insufficient
Fencing answers which holder may currently issue an operation. It does not answer whether an earlier holder's already-dispatched request reached the external world before it lost authority.

`F_new > F_old` proves current authority ordering, not historical non-execution.

Therefore:
`NEWER_FENCE + UNKNOWN_OLD_ATTEMPT != SAFE_REEXECUTION`

## Safe convergence hierarchy
Preferred, strongest to weakest:
1. Provider idempotency keyed by stable EffectID.
2. Provider authoritative operation lookup keyed by EffectID.
3. Queryable postcondition with a deterministic, unique business identity.
4. Compensating/reversal operation whose semantics are themselves reliable and fenced.
5. Explicit human/authority decision under declared risk policy.
6. Otherwise HOLD/UNKNOWN; do not claim completion or non-execution.

## Important caveat on postcondition queries
A query that merely observes the current state may be insufficient if another actor can produce the same state, if the effect is non-unique, or if the query has stale/eventually consistent semantics. The reconciliation predicate must bind the result to the intended EffectID or an equivalently unique external identity where possible.

## Irreversible effects
For irreversible effects such as sending a one-shot notification or executing an external action without deduplication, an UNKNOWN result can be permanently unresolvable. Nexo should preserve UNKNOWN as a terminal epistemic state unless later independent evidence closes it. A newer fence cannot retroactively cancel the old action.

## Retry policy consequence
Automatic retry eligibility must be a capability of the provider/effect contract, not a generic property of the executor. Candidate field:
`UnknownOutcomeRetryPolicy = {PROHIBITED, RECONCILE_FIRST, IDEMPOTENT_RETRY, COMPENSATE_THEN_RETRY, EXPLICIT_APPROVAL}`

The policy must be bound to EffectClass, provider capabilities, reversibility, and evidence quality.

## Critical distinctions
- NEWER_FENCE != HISTORICAL_NONEXECUTION
- UNKNOWN != FAILURE
- IDEMPOTENCY != FENCING
- RECONCILIATION != RETRY
- QUERYABLE_STATE != UNIQUE_EFFECT_PROOF
- COMPENSATION != RETROACTIVE_UNDO
- AT_MOST_ONCE_ATTEMPT != EXACTLY_ONCE_EFFECT
- NO_ACK != NO_EFFECT
- OLD_AUTHORITY_REVOKED != OLD_REQUEST_NOT_DELIVERED

## Nexo implication
The effect contract must classify the recovery capability before execution. For weak/no-idempotency providers, an UNKNOWN external outcome blocks automatic re-execution unless a provider-specific reconciliation or compensation proof closes the ambiguity. Authority fencing protects future admission; it cannot rewrite external history.
