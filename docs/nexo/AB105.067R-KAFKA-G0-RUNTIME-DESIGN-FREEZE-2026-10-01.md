## Runtime design finding
The current compile probe is not a runtime harness. It constructs KafkaClusterTestKit, creates a topic, invokes an Admin delete-acls call and a producer send, then closes the cluster. It does not establish the required A1 -> D0 -> D1 -> D2 -> E witness tuple.

The current TargetAuthorizer blocks every ALLOWED authorization result after delegating to StandardAuthorizer. This is a compile/API probe only and MUST NOT be promoted unchanged into runtime, because a runtime barrier must be scoped to the intended target Produce authorization and must not accidentally block unrelated authorized operations.

The exact E accessor compiles against BrokerServer.logManager().getLog(...).map(UnifiedLog::logEndOffset), but compilation is not evidence that E was observed at runtime.

## Frozen runtime transition
1. Build an isolated non-combined KafkaClusterTestKit.
2. Apply TargetAuthorizer only to the intended target broker; controllers remain StandardAuthorizer.
3. Create isolated topic/partition and install target WRITE ACL.
4. Establish and record normal ACL visibility/propagation.
5. Establish baseline Produce ALLOW on the target broker.
6. Establish target partition/leader readiness and baseline logEndOffset.
7. A1: intercept the real target Produce authorization call; delegate to StandardAuthorizer; record ALLOW; hold before returning the authorization result to Kafka.
8. D0: complete DeleteAcls at the controller/metadata-log control-plane boundary.
9. D1: issue an independent fresh Produce to the same target broker and require an observed DENY for target WRITE.
10. Only after D1 is observed, release A1.
11. D2: require the original Produce to continue through normal Kafka authorization and append path.
12. E: independently observe the target broker's UnifiedLog.logEndOffset after D2, with the partition isolated from unrelated writers.
13. Classify EXACT_RACE only if the complete A1 -> D0 -> D1 -> D2 -> E tuple is internally consistent. Partial or contradictory sequences remain UNKNOWN/non-witness.

## Source-grounding
Kafka's Authorizer API is synchronous for request authorization and is invoked on the request thread; implementations are expected to avoid blocking remote communication. StandardAuthorizer evaluates against its current in-memory ACL data. Kafka's Produce path authorizes WRITE on the topic before adding authorized request data for processing. These facts motivate the scoped barrier and the requirement for a real runtime witness rather than source-level inference.
