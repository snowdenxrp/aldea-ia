# AB105.071R — Kafka G0 D1 error-boundary resolution 2026-10-01

Kafka pinned revision: 99b940733a9f6bc409457dba7108f08421d81e42.

## Verified

Kafka authorization documentation maps normal PRODUCE to WRITE on Topic and METADATA to DESCRIBE on Topic. A topic authorization failure is represented by TOPIC_AUTHORIZATION_FAILED. This means D1 must distinguish a denied Produce WRITE from a metadata-only failure.

The pinned Kafka source also contains producer-side handling of TopicAuthorizationException for unauthorized topics.

## Runtime requirement

The producer identity should retain Topic DESCRIBE while the target Topic WRITE ACL is the permission removed at D0. D1 must capture the authorization failure as the target topic authorization failure, not merely assert a generic producer exception.

The original A1 call remains held before authorization returns to Kafka. D0 must complete, D1 must independently observe the post-revocation denial, then A1 is released. Only afterward can D2 and E establish whether the original authorized request continued to append.
