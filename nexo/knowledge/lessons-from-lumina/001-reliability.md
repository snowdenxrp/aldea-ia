# Lesson 001 — Reliability is evidence, not appearance

## General lesson
A system that looks correct in the UI is not necessarily correct internally. Critical behavior must be verified through state, behavior, persistence, and regression tests.

## Nexo application
Nexo health checks must not rely on UI output alone. Core state, event history, memory integrity, tool results, and recovery behavior need independent verification.

## Provenance
Engineering lesson distilled from the Lúmina development experience. This file intentionally contains no Lúmina runtime code or state.
