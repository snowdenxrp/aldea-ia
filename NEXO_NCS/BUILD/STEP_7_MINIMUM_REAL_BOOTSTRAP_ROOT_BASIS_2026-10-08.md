# STEP 7 — Minimum Real Bootstrap Root Basis — 2026-10-08

Status: DESIGN CANDIDATE — ATTACK REQUIRED

## Research convergence
MASTER and historical research converge on a three-part bootstrap idea: a governed genesis bundle, an authority independent of Nexo's own cognitive/runtime state, and platform/boot integrity evidence when required by the threat model. Clean recovery additionally requires an independent trust path.

Important: these are semantic requirements, not yet a mandate for TPM, cloud KMS, blockchain, human operator, or any specific vendor mechanism.

## Minimum root basis
The first Nexo trust basis is a protected bootstrap relation:
`EXTERNAL_OR_INDEPENDENT_BOOTSTRAP_BASIS → GENESIS_TRUST_BUNDLE → NEXO_TRUST_CONTEXT`

The bootstrap basis must be independently recognized under the intended threat model. The genesis bundle can describe Nexo's initial trust regime, but it cannot be the sole source of its own authority.

## Minimum semantic inputs
1. `bootstrapBasis`: independently recognized authority/trust basis.
2. `genesisBundle`: governed initial Nexo trust/constitutional references and required bindings.
3. `integrityEvidence`: only platform/runtime integrity evidence required by the threat model.
4. `independenceClosure`: dependencies and failure/trust domains showing the bootstrap basis does not derive its authority from the Nexo state it is establishing.
5. `validityState`: currentness/revocation/succession conditions.
6. `establishmentProvenance`: protected evidence generated by the bootstrap boundary.

## Required result
`ESTABLISHED` only when all root-critical conditions are actually established.
`UNKNOWN` when independence, currentness, revocation, recovery basis, or required integrity evidence cannot be established.
`INVALID` when a required condition is disproven.

## Clean recovery requirement
The bootstrap design must name a recovery path that does not depend solely on the compromised/unavailable Nexo root. Otherwise the root failure state is `TRUST_UNRECOVERABLE`, not successful recovery.

## Future evolution
A future root mechanism may change, but the semantic relation must remain stable. Root succession is a governed authority transition, not a schema migration or provider swap.

## Explicit non-goals
No Policy, admission, capability issuance, mission authority, execution, effect handling, queue, retry, operation identity, generic trust registry, or recovery orchestration is created here.
