# STEP 7 — First Trusted Fact / Circularity Attack
Date: 2026-10-08
Status: ROOT-BASIS REVIEW; NO TECHNICAL ROOT SELECTED; ACTIVATION BLOCKED

## Purpose
Attack the concrete commissioning mechanism families by asking one question: what is the first fact accepted as trustworthy, and what independently establishes that fact without relying on the candidate Nexo instance or on the authority it is meant to create?

This is a root-basis review, not an implementation proposal. It does not reopen generic self-signing/hash/provider/snapshot attacks except where a candidate changes the failure model.

|---|---|---|---|---|

## Critical distinction
The first trusted fact is not necessarily a cryptographic primitive. There are two separate foundations:
1. **Normative legitimacy:** the user's explicit, informed commissioning act is the intended source of authority under the Constitution.
2. **Technical recognition:** a channel outside the candidate Nexo trust domain must authenticate and bind that act to the exact constitutional object and challenge.

The first cannot be manufactured by a signature. The second cannot be inferred from a user's intention alone. The design must join them through an explicit, reviewed ceremony while admitting that human control/recognition and platform trust are assumptions with bounded evidence, not absolute mathematical proof.

## Candidate leading path (not approved)
The most compatible semantic path remains:
- A recognition channel already controlled/recognized by Kevin before commissioning, outside the candidate Nexo device's trust domain.
- A fresh one-time commissioning challenge that includes deployment identity, exact Constitution canonical identity/version/content digest, and ceremony context.
- An independent presentation of the constitutional identity and material summary; user explicitly approves that exact context.
- A cryptographic response from the pre-established authenticator bound to the challenge and exact transaction.
- The candidate device verifies the response against a public key/reference established independently of the candidate itself.
- The result grants only INITIAL_COMMISSIONING_BINDING_ESTABLISHED within a narrow scope; it does not automatically activate arbitrary policies, root replacement, succession or external effects.
- Any mismatch, stale revocation/currentness, unavailable channel, ambiguous presentation, shared-domain compromise or uncertain binding yields UNKNOWN/HOLD.

This path still does not specify which existing channel, authenticator, enrollment basis or trusted display is acceptable. It is not authorized for implementation.

## Adversarial attacks against the leading path
1. **Channel was never independently enrolled:** attacker inserts their key before Kevin's first use. Result: no positive binding; require independently established enrollment or hold.
2. **Both devices share one compromised account/update/recovery domain:** a single attacker can control both. Result: do not claim independence; reassess if the required independent property survives.
3. **Display omits changed constitutional clauses:** signed digest binds hidden content the user did not meaningfully review. Result: exact digest binding is necessary but insufficient; presentation contract must define intelligible scope and content review.
4. **Challenge binds only a hash, not deployment/context:** valid approval transplanted to another Nexo instance or environment. Result: reject; context is part of canonical commissioning object.
5. **Approval is replayed after revocation or interrupted commissioning:** same signed record reactivates stale state. Result: require one-time challenge consumption and currentness; if not provable, UNKNOWN.
6. **Owner is unavailable or coerced:** channel reports a technically valid signature. Result: signature supports credential control/approval input, not freedom from coercion; no claim of coercion-proof consent.
7. **Recovery replaces the independent channel:** recovery provider enrolls a new key and treats it as equivalent to the old root. Result: separate governed replacement/succession; no self-promotion.
8. **Candidate Nexo is offline:** cannot check revocation or currentness of the independent credential. Result: no protected activation unless a separately governed bounded offline rule exists; none currently approved.
9. **Valid channel approves wrong canonical object:** UI labels a Constitution "v1" but binds a different digest/context. Result: canonicalization and presentation-to-execution binding remain blockers.
10. **Independent channel and candidate verifier share a hidden trust root:** apparent independence is nominal only. Result: dependency closure required; unknown common mode means independence unproven.

## What is and is not resolved
- Resolved from existing governance decisions: initial legitimacy source is owner-authorized commissioning; independent recognition is required; the candidate Nexo instance cannot self-certify.
- Narrowed: a pre-existing owner-controlled channel with fresh challenge and exact constitutional binding is the leading semantic direction for further threat-modeling.
- Not resolved: how that channel was initially bound, which platform/credential/display is accepted, how its dependencies are validated, recovery/replacement authority, currentness while offline, and how to make the ceremony portable without provider capture.
- No evidence justifies declaring any candidate's first fact universally trusted. The chosen deployment must explicitly state the human/platform/provisioning assumptions it accepts.
- No root, credential, device, provider or protocol selected. No Trust Foundation or Constitution Authority Context implementation/activation authorized.

## Decision
Do not select a technical root yet. The semantic design has a leading path but its initial credential/channel binding is still an assumption requiring explicit acceptance and attack. This is not a reason to add a generic trust layer. It is a reason to state the root assumptions honestly and decide whether the deployment's accepted trust boundary is sufficient.

## Next exact action
Reconcile this circularity result with the Master/Constitution authority principle and the accepted independent-channel requirement. Produce a decision checkpoint that states (a) the exact trust assumptions a human-controlled channel would require, (b) which cannot be proven by Nexo itself, and (c) which mechanism properties can be independently tested. If any assumption has no legitimate owner or acceptance basis, leave the root unresolved and stop technical selection.
