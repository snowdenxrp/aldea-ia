# AB104.131 — concurrent runtime mission-state convergence — 2026-09-26

Previous: AB104.130.

Audit finding:
- AB104.130 serialized overlapping same-key effect execution at the adapter layer.
- The runtime still committed mission memory from independent stale snapshots.
- For two concurrent steps of the same mission, both calls could execute correctly but each could return/persist a snapshot containing only its own step outcome. A last-writer persistence model could therefore lose the other authoritative attempt.
- This is a distinct frontier from effect serialization: physical side effects can be serialized while mission/outcome memory still fails to converge.

Research basis:
- JavaScript async work can interleave at await boundaries, and promise chains are a standard way to serialize dependent asynchronous work. MDN documents both the interleaving semantics of async functions and sequential promise composition.
- Source: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Using_promises
- Source: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function

Hardening:
- Added an in-process runtime commit lock keyed by the shared memory object.
- Effect execution remains outside the commit lock, so independent effects are not unnecessarily serialized at the runtime layer.
- After an effect completes, the commit section reconstructs the latest durable mission state from the shared memory before applying the step outcome.
- Runtime memory is updated in place with the converged snapshot so concurrent callers sharing that memory observe the same authoritative journal.
- If a concurrent caller reaches the commit section after its step already has a terminal authoritative outcome, it returns the reconstructed authoritative mission instead of creating a second outcome.

Regression:
- Added tests/nexo/runtime-concurrency.test.mjs.
- Two independent steps from one mission execute concurrently against one shared memory object and execution journal.
- Both outcomes must remain in memory; both returned missions must contain both completed steps; both returned memory references must converge to the shared memory object.
- Added the regression to the npm test script.

Scope:
- This closes the in-process shared-memory runtime convergence gap.
- It does NOT prove cross-process or distributed convergence. If deployment can run multiple processes with independent memory objects, durable transactional versioning/CAS or an equivalent shared coordination primitive remains necessary.
- The effect adapter's shared in-flight registry and this runtime commit lock are intentionally separate: one protects overlapping physical effect execution; the other protects authoritative mission-memory convergence.
