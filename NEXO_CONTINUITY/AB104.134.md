# AB104.134 — Nexo simulation persistence boundary + restart recovery — 2026-09-26

Previous: AB104.133.

Validated finding from canonical code audit:
- `scripts/simulate.mjs` persisted world/agents/events but did not carry Nexo mission memory.
- `createSimulation()` did not own a normalized Nexo memory object.
- `executeLuminaNexoStep()` could therefore receive an external memory object, but the simulation itself had no canonical memory owner to survive a simulation restart.
- The existing reconstruction tests covered serialized memory objects, but not a real file save -> reload -> reconstruction boundary.

Repair:
- `src/simulation.js` now initializes `simulation.nexoMemory` through `createLearningMemory()`, preserving the normalized Nexo mission/execution/outcome journal as simulation-owned state.
- `src/nexo/runtime.js` now uses `simulation.nexoMemory` when no explicit memory is supplied, and binds an explicitly supplied memory into the simulation when absent. The execution journal used by the Lúmina effect adapter therefore follows the simulation's durable memory boundary.
- `scripts/simulate.mjs` now loads persisted `nexoMemory`, passes it into `createSimulation()`, and persists it in the same world-state envelope.
- Persistence now writes a temporary file and renames it into place instead of truncating the live state file directly.
- State schema version is advanced to 5 while old states remain readable.
- Added `tests/nexo/simulation-restart-persistence.test.mjs`, which performs an actual temporary-file save, reload, simulation reconstruction, and Nexo mission reconstruction.
- Added the regression to the package test script.
