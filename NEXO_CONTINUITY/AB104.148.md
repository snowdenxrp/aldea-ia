# AB104.148 — prepared-intent durability gate — 2026-09-26

Previous: AB104.147.

## INVESTIGAR
Research confirms the important distinction between atomic local state and an external side effect. The transactional-outbox pattern documents the crash gap: a process can commit durable state and crash before sending, or send and crash before recording that it sent; therefore recovery requires durable intent plus idempotency/reconciliation rather than assuming exactly-once delivery. citeturn0search1

Node.js v22 documentation confirms fs/promises operations are asynchronous and not synchronized/threadsafe; concurrent modifications need explicit coordination. It also documents `writeFile(...,{flush:true})` support, which uses `filehandle.sync()` after a successful write, but this does not by itself make a multi-step external effect atomic with the state file. citeturn0search3

## CONSTRUIR
Commit `5bde125c3b21e6ca6262c3d04c361218fc537d75` adds an explicit `persistPreparedIntent` hook to the effect adapter.

New contract:
1. create `prepared` journal entry;
2. invoke `persistPreparedIntent`;
3. only if that hook succeeds may the handler execute;
4. if the durable-intent hook fails, return `blocked/EFFECT_INTENT_PERSISTENCE_FAILED` and do not invoke the effect handler.

Commit `43e28c55dde0cec2e58daf5b2e2373d44c06d1af` adds a focused test for this ordering and failure boundary.

## IMPORTANT SEMANTIC STATUS
The adapter now has the correct *extension point* for a durable prepare-before-effect protocol, but the Lúmina runtime has not yet wired this hook to a real `persistState()` checkpoint.

Therefore this is NOT yet a claim of end-to-end durable prepare-before-effect execution.

## NEXT EXACT ACTION
Wire the hook through `executeLuminaNexoStep()` without silently inventing a persistence owner:
- the caller that owns the canonical state/revision must provide the checkpoint callback;
- checkpoint must use revision/lock semantics already established in `persistState()`;
- test crash/failure between prepared checkpoint and handler;
- test handler exception after durable prepare and verify restart leaves the prepared entry for reconciliation;
- test completion checkpoint separately;
- obtain fresh CI evidence.

Do not hide the persistence ownership decision inside the effect adapter.
