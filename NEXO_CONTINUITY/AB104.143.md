# AB104.143 — prepared-effect reconciliation boundary + Nexo memory persistence contract — 2026-09-26

Previous: AB104.142.

## INVESTIGAR
- Re-read current effect-adapter, Nexo memory, orchestrator, assistants workflow, and world-state persistence code.
- Confirmed the crash-window ambiguity: a durable/in-memory `prepared` intent does not prove that an external effect did not occur.
- Confirmed assistants workflow previously kept `simulation.nexoMemory` and `.lumina-assistant-memory.json` operationally separate; Nexo mission plans generated by the assistant path were not persisted into the world-state Nexo memory.

## ANALIZAR
- Unsafe behavior identified: a restart containing `status:"prepared"` automatically retried the handler. For a non-idempotent physical/external effect, this can duplicate the effect.
- Recovery must therefore distinguish:
  - completed durable result;
  - prepared / effect outcome unknown;
  - explicit reconciliation evidence;
  - safe fresh execution.
- The assistant memory and Nexo mission memory are now treated as distinct stores with an explicit persistence boundary:
  - `.lumina-assistant-memory.json`: assistant-learning/report memory.
  - `world-state.json.nexoMemory`: Nexo mission/attempt/execution memory.
- Assistant workflow now persists the Nexo mission into world-state using the existing revision-checked, filesystem-locked `persistState` path.
