# AB104.136 — CI exposed durable runtime reconstruction regression — 2026-09-26

- All earlier audit tests and the effect-adapter tests reached the Nexo runtime test before failure.
- Concrete failure: tests/nexo/runtime.test.mjs:91 expected secondMulti.mission.steps[1].status === "completed", but observed "planned".
- Cause: durable runtime commit reconstructs the mission from persisted memory. The durable plan intentionally stores unexecuted steps as "planned" until their outcome is recorded. After the adapter had already executed step-2 successfully, commitRuntimeOutcome reconstructed step-2 as "planned" and called advanceNexoMission directly. advanceNexoMission only applies an outcome to a step in "executing" state, so it returned the reconstructed "planned" step unchanged while the runtime result itself reported completed.
- This is a real runtime/persistence interaction defect, not an infrastructure failure.

Repair:
- Commit cbbbf7821e867bc4386424f3dec243e55df6313a.
- In commitRuntimeOutcome, when the reconstructed step is non-terminal and still "planned", restore only that already-authorized step to "executing" before applying the authoritative adapter outcome.
- The repair preserves the dependency checks that happened before the effect ran; it does not reopen unrelated steps or weaken terminal-state protection.
- Same-step terminal reconstruction still returns the durable authoritative result without replaying or overwriting it.
